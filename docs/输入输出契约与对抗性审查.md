# 首次项目建设：输入输出契约与对抗性审查

> 核验对象：`docs/data/quotation.json` 与主 Skill、模板、站点。此处核验的是**流程设计、文件依赖与证据规则**，不是客户项目已经真实执行或上线的证明。

## 1. 质量判断

| 检查维度 | 故意假设的失败情形 | 修正方式与证据 |

| 架构→数据库 | 数据域拆分忽略数据保留、容量与实际运行边界 | S05显式读取 `项目基线.md` 和S04的已批准交互、数据Owner；不做具体DDL |

## 3. 审核时做的反向追踪

1. **输入是否真实可读取**：以文件存在性、版本、确认状态、运行权限和可访问日志为准；凡是可选资料缺失必须注明是否影响本节点，不机械全停或无证据继续。
2. **上游输出是不是下游输入**：重点核对 S03→S04/S05/S09、S04→S05/S07/S09、S07→S08、S08→S09/S10/S11、S09→S10/S12、S13→S14、S14→S14H、S14H→S15、S15→S16、S17→S18→S19。
3. **原型不可被替代**：实现节点 S12、联调节点 S14、人工节点 S14H 必须对照现有 `code/fld/` 路由、页面、组件、视觉，不允许创建第二套界面。
4. **失败不等于已完成**：SQL草案、模拟第三方、只生成的人工测试单、未授权生产预演均不能标为真实通过。
5. **决策不等于只写图**：Grill未确认的改变组件、通信、权限和状态Owner的取舍，要停止，取得批准并将已确认结论更新ADR或设计记录；不再返回to-spec重复问已定问题。

## 4. 持续校验与局限

- `python3 scripts/audit_contracts.py`：审查关键I/O、Grill/缺陷回环、路径命名及来源说明是否完整。
- `python3 scripts/build_site.py`：执行静态审计、生成离线站点及Skills压缩包。
- `node scripts/smoke_ui.cjs`：在GitHub Actions中真实模拟点击阶段、Skill预览与工作区通用工具。
- 这些检查只能证明**导航/规范本身没有明显结构性缺陷**，不能证明客户系统已经通过代码审查、人工验收、第三方测试或生产部署。
