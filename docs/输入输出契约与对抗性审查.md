> 设计与静态约束核验，不代表客户项目实际部署完成；依据2026-10-10仓库中当前导航数据实时重建。

## 1. 对抗式失败注入与纠错

| 怀疑故障 | 核对及处置 |
|---|---|
| 整体架构只读取PRD而遗漏工程/环境/对接/新增分类 | S04递归读取`docs/input/`全部实际文件，结合项目基线和既有源码；不存在的资料标缺口 |
| S05或S09绕过基线自行决定数据库/组件 | 显式输入项目基线及已审定整体架构，违反全局骨架返回技术总监 |
| Grill仅显示在流程图、运行时不执行 | S04架构Skill与S09详细设计Skill内部按需调用官方`grill-with-docs`，逐轮基于事实提问并形成可追溯决策 |
| 设计阶段输出可执行SQL并声称已迁移 | S09只交`迁移设计草案.md`；S12 TDD产生真实版本化SQL，差异须回写设计 |
| 开发环境绑定某个人的Windows固定路径 | S06先由用户填写环境事实，检查当前主机/权限/已有依赖；无固定`D:/company/environment/` |
| 开发环境改文件名而下游仍读旧文件 | 全部S07/S08/S12使用`docs/output/04-开发环境/部署步骤与执行记录.md` |
| Matt内置code-review不留存结果，下一步丢失证据 | S12分别输出`实现与自动验证记录.md`和`代码审查记录.md`；S14H和S15显式引用 |
| 以自动测试通过冒充真实用户业务验收 | S14H由AI生成待执行用例，人亲自操作并在同一`人工测试用例与结果.md`回填；S16沿用逐模块文件 |
| Bug一改完就收口，无真实根因和人工复测 | S14B走Matt六阶段诊断，重跑相关TDD/Review并人工复测，未闭环S15不标已验收 |
| 本轮第一轮项目状态文件没有生产者 | S08首次创建项目实施状态，以后只更新不覆盖已签收模块 |
| 模块计划文件名只有简称无法被执行 | S09输入分别列出模块清单、模块依赖关系、本轮计划、前置依赖检查的完整路径 |
| 静态站点与Skill/导航步骤数量不一致 | 构建使用真实步骤唯一性校验，UI点击回归验证7步项目设计、当前模块迭代及Grill存在 |
| 参考来源只写网址，不写采用什么 | `skills/REFERENCES.md`与网站来源标签分别列实际借鉴机制及完整采用/改造边界 |

## 3. 反向依赖重点核验

**全局资料链**：输入就绪S01→工程基线S03→整体架构S04→数据库总体S05→开发环境S06→模块识别S07；其中S04读取所有原始类别并在必要时内部Grill。

**模块实施链**：S07模块清单/依赖→S08实施状态/本轮计划→S09模块设计/迁移草案→S10 Spec→S11 Tickets→S12真实TDD/内置Review/集成验证→S14H人工结果→S15收口→S16系统总验收；S14B Bug失败返工回S12相关测试及内置审查再人工复测。

**上线链**：S16跨模块系统验收→S17非功能评审→S18生产机/备份恢复及回滚预演→S19实际发布及交付。

**证据规则**：工程资料或环境表的预计配置不等于系统实测值；SQL草案、模拟第三方、AI预生成用例、无权限的部署指令均不能冒充真实通过。

## 4. 如何复核

- `python3 scripts/audit_contracts.py` 检查关键输入输出、Skill对应、内部Grill、内置Review证据和人工回环。
- `python3 scripts/build_site.py` 运行前置审计、生成单文件网站与Skills ZIP。
- GitHub Actions 执行 `node scripts/smoke_ui.cjs` 的真实DOM点击回归及Skills预览，不以纯字符串构建成功替代交互通过。
- 此审计是**研发工作区的规范验证**，没有针对真实客户项目执行代码、部署、人工签收或第三方联通。
