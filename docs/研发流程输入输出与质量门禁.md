# 研发流程输入、输出与质量门禁

以下内容来自当前 `docs/data/quotation.json` 中的正式步骤契约，不代表任何项目已实际验收。

## 1. 原则

- 从真实PRD、已有前端原型、后端框架及工程和第三方资料中提取事实，不重造系统。
- 项目基线只交付一份正式文件；S04/S05/S07审核融入正文或对话，不创建独立审核文件。
- S09按module_key维护模块设计；S10/S11使用Matt原版独立feature-slug/Tracker，不混淆身份。
- 真实自动/人工测试、签收、预演与生产交付分别保存证据，模拟不等于实际通过。

## 3. 阶段放行说明

- S07的10个模块是粒度评审阈值，并非强制上限。
- S09第1章承担本轮范围/依赖，第4章承担迁移设计思路，不新造旧文件。
- S12原版实现内置TDD和code-review；S14H待人测生成≠实际签收。
- S14B可由CI、设备、第三方、生产或人工测试来源触发，应回到原故障来源复验。
- S16仅输出一份系统验收报告.md（矩阵与缺陷闭环置于正文）；S17执行系统性能验收（含非功能质量门禁）；S18为**唯一的上线部署步骤**，在内部先运行release-preflight，再调用release-delivery，按开发/测试/正式环境及首次/更新保留预演和发布证据。开发/测试应用部署可发生于模块迭代期，正式发布必须有S16/S17放行。

## 4. 验证

使用仓库的全仓审查、契约审查、15项场景演练、站点构建和DOM交互验证依次把关。
