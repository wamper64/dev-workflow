# 研发流程输入输出与质量门禁

本文件是导航的**现行执行契约**，不包含版本日志和过时步骤。以下是Skill必须完成的工作，不表示特定客户项目已经实际验收。

## 1. 执行原则

| 条款 | 验收或阻断规则 |
|---|---|
| 真实输入 | 从 `docs/input/` 和 `code/` 读取实际证据，不固定前后端目录名或强加不存在的服务 |
| 项目基线 | 只输出可判定工程约束；未裁定的量化目标不得发布为正式基线 |
| 整体架构 | 组件/交互与关键业务链路必须双向映射，正常、异常与Owner均闭合 |
| 数据库总体 | 整体规则→数据流程→核心表/字段/ER关联必须可追溯，模块局部DDL留给编码 |
| 初次部署 | 一环境一配置，单独批准后才部署；真实服务健康及异机验证有证据 |
| 模块池 | 业务职责/核心对象生命周期决定拆合；不能按页面/表机械拆分 |
| 模块迭代 | S09同时完成本轮选择、依赖门禁、详细设计；S10 Spec与S11 Tickets独立留历史 |
| 实现与人测 | Matt原版implement-spec内TDD与code-review；人测未执行不得签收，失败进入Bug复测 |
| 上线与交付 | 系统验收、性能/安全、备份/回滚、生产部署均需实际操作或检查记录 |
| 变更约束 | 触碰总体组件/关键链路返回架构审查，核心表/字段/关联/Owner返回数据库总体审查 |

## 3. 跨步骤不可混淆的边界

- **Skill出现在哪一步，不等于只能在这一步调用**：/diagnosing-bugs 是贯穿开发、CI、联调、人工测试与线上反馈的按需能力；放在人工测试之后仅表示一条常见迭代闭环。错误来源不同，所需入参、证据与返回验证路径也不同。
- **故障来源决定复验位置**：人工用例失败需原用例人工复测；自动化/CI失败需重跑原检查；设备、第三方与生产故障需真实链路或获授权监控验证。没有对应来源的用例文件无需新建。
- **正式验收不能假设前置工作已成功**：人工测试先核对实际自动化证据，全项目验收先检查真实签收覆盖；缺少关键证据应提示阻塞，不预填已通过。


- **项目级 vs 模块级**：S07只形成模块清单、边界、依赖与人工审核；S09选真实就绪的本轮任务并做详细设计；S11才生成逐张可领取的实现Ticket。
- **数据库设计 vs 执行SQL**：S05锁核心表、核心字段和ER；S09补本轮模块字段及迁移草案；S12 TDD阶段生成经测试的版本化SQL。若改变冻结契约需先回相应上游。
- **部署配置 vs 实际运行**：S06配置确认是第一关，远程执行/本机及异机验收是第二关；模板与未知环境数据不能算执行证据。
- **实现自动验证 vs 人工测试**：仅真实人工操作者回填结果/证据；同一用例复测保留历史，项目实施状态只在签收后更新。
- **复盘 vs 签收**：Matt retro只评估AI开发会话的工程环境改进，不代替人测签收、上线批准或全项目验收。

## 4. 可执行校验

`python3 scripts/audit_contracts.py` 校验主流程、Skill引用、关键产物和页面速查；`python3 scripts/build_site.py` 同步构建网站/安装包；CI中的 `scripts/smoke_ui.cjs` 检验真正的页面点击与Skill文件显示。
