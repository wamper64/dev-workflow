# 报价业务人工测试示例（待实际执行）

> 本示例展示 `manual-testing` 从Matt原版 `implement-spec` 的真实自动测试及Review证据中识别人测缺口。下表的场景、账号及预期均为假设；没有执行人及证据时，不得填“通过”。

## 1. 自动验证覆盖判定

| 角色×场景 | 真实自动测试证据（执行后填写） | 分类及处理 |
|---|---|---|
| 技术人员×参数版本确认 | 待关联本次TDD/接口测试命令与结果 | 尚无证据：应补自动化，不直接交人测 |
| 业务人员×原型核对体验 | 自动化不能代替实际视觉判断 | 需要人工验证 |
| 审批人员×真实多角色流转 | 若角色及环境可用，核对自动覆盖边界 | 实际账号未到位则受阻 |

## 3. 阻塞与签收

第三方未接通时，H-003应记为“受阻”，不得将Mock作为真实通过。测试失败需关联Bug和原用例ID，修复后由人复测、保留首次失败事实。开发技术签收及项目经理业务签收均基于实际证据，不能由AI代填。
