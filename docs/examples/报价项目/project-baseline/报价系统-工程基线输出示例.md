# 报价系统项目工程基线——定稿形态示例

> **全部数值、版本和约束均为虚构演示，假设已由相应负责人确认；并非真实报价项目、已有代码或客户服务器的事实。** 本文件只展示工程约束如何写，不给出需求功能清单、架构拓扑或具体服务资源分配。真实运行时先在对话内自动预填并确认缺口；只有负责人裁定后才正式生成 `项目基线.md`，不新增前置确认表文件。

## 1. 工程原则与取舍

| 适用条件 | 必须保证的结果 | 禁止或可检验边界 |
|---|---|---|
| 自动提取与人工确认之间 | 经授权人工确认的数据才可以成为正式业务依据 | 未确认的自动解析候选不得覆盖正式数据 |
| 正式报价与修订之间 | 历史确认版本及其依据可追溯 | 新计算不能静默改写已审批版本 |
| 第三方处理和失败之间 | 只能报告真实状态 | 超时或模拟结果不得显示为真实成功 |

## 2. 工程禁止、复用与责任边界

| 范围 | 已批准的项目级约束 | 如何判断违规 |
|---|---|---|
| 已有前端原型 | 在现有原型基础上继续开发，整体视觉和公共组件保持复用 | 出现与原型平行的UI体系或未获准重做主页面 |
| 已有后端权限 | 不得绕开既有身份和数据权限控制 | 未经授权可以跨项目读取或修改记录 |
| 外部调用 | 第三方/AI调用必须遵守当前用户可用的业务权限 | 服务账户可以绕过用户限制执行敏感操作 |
| 工程边界 | 不得擅自接入未经批准的公网云服务 | 在内网限制条件下出现未许可出网依赖 |

## 3. 技术兼容与目标环境

### 3.1 技术及复用限制（仅演示的批准值）

| 分类 | 示例批准版本 | 允许变更条件 |
|---|---|---|
| 前端 | Vue 3.5、Vite 6、Element Plus 2.9 | 重大升级需兼容审查与技术负责人批准 |
| 后端 | Java 8、Spring Boot 2.7、RuoYi-Vue 3.8.8 | 不得未经批准更换基础工程 |
| 存储和服务 | MySQL 8.0、Redis 7.2、Nginx 1.24 | 产品替换需按兼容性和资源约束重新评审 |

### 3.2 生产环境硬边界

| 对象 | 模拟已批准的目标 | 禁止边界 |
|---|---|---|
| 部署资源 | 单台x86_64机器、8vCPU、16GiB RAM、500GB SSD | 不得依赖未批准的第二台业务服务器完成验收 |
| 操作系统 | Ubuntu 22.04 LTS，Docker Compose部署 | 不得假定其他OS的运行能力已经验证 |
| 网络 | 客户内网访问，不默认公网出站 | 外部服务依赖必须另获批准 |
| 资源余量 | 所有必要运行单元总占用不得突破物理约束；必须保留OS及故障波动余量 | 架构设计须进一步证明CPU、内存、磁盘与备份空间闭合 |
| 恢复介质 | 假设另有经验证可用的离机备份存储 | 本机磁盘副本不得被冒充为离机灾备 |

**这里仅规定整机上限和余量要求**，MySQL/API/Worker等实际组件及各自CPU、内存配额由整体架构确定。

## 4. 使用规模、业务容量与任务边界

| 对象 | 模拟已批准的数值与口径 | 适用条件 |
|---|---|---|
| 同时在线 | 50人 | 保持业务会话，不等同请求并发 |
| 典型HTTP请求目标 | 同时在处理12个常规请求 | 不含后台执行任务本体；按约定峰值场景压测 |
| 后台计算执行 | 最多同时2个任务 | 真正执行中，不能把排队当执行 |
| 后台等待任务 | 最多排队10个 | 满额拒绝并报告可识别状态 |
| 单任务执行时长 | 最长20分钟 | 从开始运行计时；端到端含排队等待另有目标 |
| 业务数据 | 初始20GB、每年新增12GB | 模拟含索引和审计，五年约80GB，仍需复核容量 |
| 附件和输出文件 | 初始10GB、每年新增22GB | 五年约120GB，须包含备份和临时空间 |
| 业务对象量 | 每年新增约3000个报价项目 | 数据规模口径应与性能测试保持一致 |

注意：RPS、同时HTTP请求、任务等待目标应有实际业务使用情景、AI推导和负责人裁定，不以50在线机械推导。演示数值不是本Skill默认配置。

## 5. 数据、安全与保存期限

| 对象 | 模拟已批准的工程限制 | 起算点及检验边界 |
|---|---|---|
| 正式报价及确认版本 | 保留5年，历史版本不可静默覆盖 | 项目归档或正式终止日起算 |
| 人工确认参数与修订 | 保留5年；修订需保留依据 | 与所属项目的最终版本一致 |
| 计算依据及相关附件 | 保留5年；在被有效版本引用时不得提前删除 | 项目归档或终止日起算 |
| 审批历史和业务审计 | 保留5年 | 保留主体、时间及引用的业务版本 |
| 普通运行日志 | 保留180天，同时有容量清理机制 | 日志产生日起算；不混同业务审计 |
| 身份与数据权限 | 读取/修改按服务端当前用户权限执行 | 界面隐藏或AI提示不得代替真实鉴权 |

## 6. 性能、稳定与故障恢复

| 关键目标 | 模拟批准值 | 统计/验证边界 |
|---|---|---|
| 常用项目列表 | 服务端P95 ≤2.0秒 | 约15,000个项目，12个常规HTTP并发 |
| 详情读取 | 服务端P95 ≤1.5秒 | 同一数据集和目标部署环境 |
| 提交保存 | 服务端P95 ≤3.0秒 | 事务完成并返回结果，不含另一个后台任务执行 |
| 任务受理 | 服务端P95 ≤1.5秒 | 返回任务受理状态，不代表计算已完成 |
| 常规服务端失败 | 在约定负载下≤0.5% | 排除符合协议的用户输入校验失败 |
| 稳定性 | 目标负载连续运行72小时，不得发生资源无界增长或进程失控 | 整机资源及连接/队列/日志均不得持续单调增长造成不可用 |
| 数据库及附件RPO | 最大允许损失24小时 | 已确认的离机备份能覆盖数据/文件 |
| 业务环境RTO | 最长8小时恢复到可用 | 包括必要配置、身份、依赖及真实备份介质 |

## 7. 运维交付及变更限制

| 范围 | 必须保证的项目级结果 |
|---|---|
| 可运维 | 可识别资源满载、应用异常、后台任务失败及备份失败 |
| 可恢复 | 数据、附件和必要配置具备与RPO/RTO相容的可恢复副本和演练依据 |
| 交付条件 | 能在第3章批准的环境中部署、验证、升级和回退 |
| 变更边界 | 技术主版本、硬件资源、数据保留期、并发/性能目标、人工确认及权限原则改变时须重新评审，不得静默放宽 |

## 8. 按需项目特殊约束

| 来源条件 | 必须或禁止的结果 | 可判定方式 |
|---|---|---|
| 需人工确认的重要业务版本 | 未确认候选不可进入正式报价处理 | 通过未确认直接提交的负面验证必须被拒绝 |
| 存在多级审批 | 关键操作权限和原审批历史不可因驳回或重提丢失 | 操作人、版本与结果均可追溯 |
| 存在真实第三方调用 | 第三方失败不得被写为本系统已执行成功 | 失败或超时场景显示真实状态并保留证据 |

> 本例为**工程约束的展示形态**。这些数字只在模拟负责人裁定后成立；在真实项目中不得使用演示数据直接生成基线，更不得把后续架构分配方案提前写在基线内。
