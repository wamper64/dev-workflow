# 调用 project-baseline（报价项目仅作为演示）

**输入**：docs/input/需求资料/ 中已确认PRD和原型，工程/环境/对接资料，以及真实的 code/ 前后端工程（不假设子目录名）。

**本Skill不写需求、不做设计，只输出工程约束。**

执行：
1. 读取全部输入，提取已给出的数量、频率、版本、精度、期限等可量化事实；抽取工程禁止事项、已有资产复用、第三方责任和项目特殊规则。
2. 检查八项通用核心维度和实际触发的专项；区分已裁定、现状、可推导候选和未知。
3. **对话内自动预填**已有文件与代码能够证实的约束，只向用户询问缺失、冲突和待负责人裁决的项目级边界；不生成前置确认表文件。
4. 用户确认后，AI按业务规模估算候选RPS/并发和数据容量，技术负责人裁定；核查资源上限、性能、数据留存和RPO/RTO的闭合。
5. **最终输出** docs/output/01-项目基线/项目基线.md；核心指标未裁定则明确阻塞。

验证：最终基线不得列功能清单，也不得提前指定表、API、Worker数量或组件资源配额；禁止事项须可二值判定，量化指标须有单位和口径。

示例数字仅用于说明，不代表报价项目或其他客户已确认的配置。
