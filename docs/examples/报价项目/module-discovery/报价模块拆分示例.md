# 报价系统模块识别示例（候选划分，未核实真实完整PRD）

| 候选业务模块 | 职责 | 典型依赖 |
|---|---|---|
| 用户与授权 | 登录、角色、项目访问及任务处理权限 | 若依框架现有用户、权限 |
| 报价项目 | 项目主状态和项目ID | 身份与数据权限 |
| 术语字典与模板 | 参数同义归一、报价模板版本 | 项目与字典管理规则 |
| 历史计算单 | 历史项目与计算单检索/引用 | 项目、数据版本引用 |
| 需求解析与核对 | 上传、自动候选解析、人工确认参数 | 项目、字典与外部接口可用性 |
| 计算单匹配 | 以确认参数版本进行匹配 | 历史计算单、人工确认版本 |
| 成本与报价 | 成本核定、报价生成、版本维护 | 匹配结果、模板、授权 |
| 审批及成交归档 | 多级审批、驳回重提、正式输出归档 | 报价版本、项目权限 |

这些是按业务闭环组织的**可能分组**，绝不是强制8模块，也不代表已读全量报价PRD。核心能力是否再细拆（例如审批与归档）取决于真实职责、数据域及模块能否独立验收。
