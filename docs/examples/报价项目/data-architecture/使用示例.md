# 数据库设计（总体） · 使用示例

**场景**：报价系统首次项目建设；以下仅作候选示范，未读取真实客户完整Schema，不代表已审批。

**调用**：`/data-architecture`

**参考输入**：
- `docs/input/` 已确认PRD/原型、对接与工程资料
- `docs/output/01-项目基线/项目基线.md`
- `docs/output/02-整体架构/整体架构设计.md`（关键业务链路、数据Owner）
- `code/` 真实已有表、迁移和ORM（可读时核实）

**执行顺序**：整体数据规则 → 报价关键数据生命周期 → 核心表、字段及ER关系 → 存储/容量/安全支撑 → 两轮审核。

**示意主链**：报价项目建立 → 需求参数形成与人工确认 → 方案/成本计算引用参数版本 → 正式报价版本形成 → 审批与归档保留结果和引用。数据流程需明确每次重算/驳回后新版本如何追溯、哪些状态不能互相覆盖。

**核心表候选示例**（字段仍需对真实系统补证据）：项目表含项目唯一标识；参数版本表含项目引用、版本号、确认状态；报价版本表含项目引用和参数版本引用、报价状态；审批记录表含报价版本引用、处理动作和时间。**候选核心字段**必须在正式设计填写名称、存储类型/精度、必填/唯一约束、跨表基数和Owner；不能只提交“存在这些数据域”。

**验收**：技术总监沿“整体规则→关键数据流程→核心表/字段→ER关联→Owner及历史恢复”审核；具体辅助表、非核心字段/索引、DDL留给模块S09/S12。
