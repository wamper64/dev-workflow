# 上线就绪评审使用示例（报价业务演示）

**调用**：`/release-readiness`

**输入**：项目已批准工程基线、S16实际业务验收证据、现有部署/监控、性能与恢复验证材料。

**执行流程**：提取指标及量纲→核对测试负载与环境→测量P95/错误率/资源→核验数据留存、鉴权与备份恢复→列不达标/受阻及修复责任→技术总监签署放行。

**示例量化核对（全部为虚构数据）**：

| 指标 | 批准目标 | 实测前提 | 如何裁决 |
|---|---|---|---|
| 审批列表响应 | P95≤2秒，12并发，15,000条业务记录 | 若实际只用10条记录测得300ms | 负载不符，不能标达标 |
| 备份恢复 | RTO与RPO由真实项目基线决定 | 只有备份任务成功日志，尚未实际恢复 | 恢复目标未验证，标受阻 |
| 资源占用 | 采用当前批准的CPU/RAM/磁盘预算 | 必须测量目标环境及对应压测持续时间 | 无实测不得宣称充足 |

**输出**：`docs/output/07-系统验收/性能安全检查.md`、`docs/output/07-系统验收/上线评审结论.md`。

**放行**：以真实条件、真实结果和风险审批为准，不把测试计划或开发机的偶发运行成功当上线批准。本文件不是实际测试结果。
