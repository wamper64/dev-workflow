# 系统验收（非功能质量）· 报价系统示例

> 本例用于说明如何从实际批准指标得到测试结论，不代表报价客户服务器、访问量或恢复能力已经得到验证。

## 输入

- `docs/output/01-项目基线/项目基线.md`（已批准负载、资源、保留及RPO/RTO）
- `docs/output/02-整体架构/整体架构设计.md`（运行拓扑及组件预算）
- `docs/output/07-系统验收/系统验收报告.md`（真实跨模块结果）
- 目标环境的负载、运行、备份/恢复与安全权限验证证据

## 验证项目

| 审核维度 | 必须按真实资料填入的值 | 证据与失败路径 |
|---|---|---|
| 性能 | 并发/RPS、P95、任务时限、测试数据集与环境 | 实际测试命令、响应及异常率；不达标退整改 |
| 容量 | CPU/RAM、连接数、磁盘与日志增长、容量余量 | 负载中及持续运行的真实监控 |
| 数据保留 | 正式报价版本、附件、审计等已批准保留对象（按PRD） | 实际存储、归档与删除策略 |
| 恢复 | RPO、RTO、备份副本和真实恢复操作 | 未演练不能冒充具备恢复能力 |
| 安全 | 不同项目与角色的服务端鉴权、密钥隔离 | 真实越权拒绝与敏感信息检查 |

**执行顺序**：提取目标→在约定负载/数据集下测量→与阈值比较→列阻塞/风险→技术总监评审。

**输出**：`docs/output/07-系统验收/性能安全检查.md` 及 `上线评审结论.md`。真实关键指标未达到要求或缺少必要证据时不得标“上线就绪”。
