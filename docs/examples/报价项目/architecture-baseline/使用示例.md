# 整体架构设计 · 报价系统使用示例

> 仅示范设计过程与证据深度。该项目的PRD、原型和真实代码未随本仓库提供，示范组件、协议、资源均不是已审批事实。

## 输入

读取 `docs/input/` 中已确认PRD、工程/环境/对接资料，`docs/output/01-项目基线/项目基线.md`，并扫描真实 `code/` 下原型路由、复用组件、若依后端入口与已有依赖；按需使用GLOSSARY和ADR。

## 执行主链

1. 从角色×核心场景选出需跨组件闭环的主链（如资料上传→需求解析→人工核对→报价审批）。
2. 针对每条链绘出**实际业务处理**：输入来源→校验→权限/规则判断→状态/数据写入→后续任务/通知→结果与失败恢复。
3. 依据关键链路反推**组件架构**：已有前端/后端的可复用代码落点、职责/非职责、Owner、通信协议、存储及运行部署；不得仅画Web→API→数据库。
4. 双向核对“业务步骤→组件/Owner/交互”和“组件→业务链路/公共支撑依据”，并按条件启用Agent/第三方/长任务专项。
5. 对跨组件协议、状态权威、超时、幂等、权限、资源预算和A/B/C冻结项进行必要Grill与两轮审核。

## 示例检查

| 核对维度 | 具体必须确认 | 应形成的产物 |
|---|---|---|
| 工程复用 | 真实原型组件、路由及后端框架、允许依赖 | 工程复用和代码落点矩阵 |
| 组件与交互 | 谁负责需求解析、人工确认、报价版本及审批；请求/回调/身份 | 组件总表、Owner与交互矩阵 |
| 核心链路 | 上传→任务触发→异步执行（如适用）→写候选→人工确认及失败恢复 | 处理流程图、异常/状态矩阵 |
| 运行与质量 | 已批准运行环境、资源预算、监控与恢复约束 | 运行拓扑与容量预算 |
| 决策审核 | 重大分歧、架构冻结和跨团队合同 | 架构评审记录、必要ADR |

**输出**：`docs/output/02-整体架构/整体架构设计.md`；审核结论合并到整体架构设计正文，不另出评审记录文件；所有示例技术选型都须通过真实项目资料和技术总监审核。
