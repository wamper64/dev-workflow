# 分环境、首次/更新部署预检与回滚门禁

1. [ ] 明确开发/测试/正式环境，以及首次应用上线或已有版本更新，不将 S06 基础设施初次部署误认为应用上线。
2. [ ] 核对目标机资源、服务、网络/端口/Compose/卷/DB 隔离及账号授权；实际状态必须现场核验。
3. [ ] 绑定 Git Commit、构建/镜像 digest、SQL checksum、配置摘要、目标环境及审批记录的发布指纹。
4. [ ] 首次部署：核对已有基础设施与启动依赖、初始数据和实际业务入口；版本更新：核对现网版本、迁移、兼容、业务连续性及恢复点。
5. [ ] 备份数据/附件/配置，**仅在隔离副本/实例实际验证恢复**，不得覆盖生产权威库。
6. [ ] 仅在授权隔离环境演练本次首次/更新路径的数据库迁移、应用部署、业务冒烟及回滚或安全的前向修复。
7. [ ] 正式环境检查 S16 业务验收、S17 系统质量验收及上线批准；开发/测试可以按迭代需要预演应用发布，不强制先有正式上线评审。
8. [ ] 任何需要写入/删除生产数据或卷的危险操作须**单独授权**且注明目标/影响/停机与恢复方式。

## 关卡与产物

- 正式产物：`docs/output/08-上线交付/部署预演.md`、`备份回滚方案.md`。
- 技术总监审核正式环境预演，开发/测试由被授权的环境责任人核对。缺实际证据为受阻，不写通过。
- 发布指纹变化时旧预演/审批不能自动沿用，按受影响的业务验收、非功能验收和回滚范围重新验证。
