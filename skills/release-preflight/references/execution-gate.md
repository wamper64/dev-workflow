# 生产环境检查与部署回滚预演的核查标准

1. [ ] 在目标生产服务器或已授权的等效环境实际验证CPU/内存/磁盘、操作系统、网络、Docker版本和存储权限；不能把环境资料的计划配置当实测环境事实。
2. [ ] 准备不可变版本的前后端构建、SQL迁移清单、配置样例、密钥注入和第三方连通检查；禁止实际口令写进仓库。
3. [ ] 先制作数据/附件/配置的必要备份，并**仅在隔离副本/实例实际验证能从备份恢复，不得覆盖权威生产库**；保存可复核命令与结果。
4. [ ] 在独立或经批准的预演环境执行数据库增量脚本和应用发布，检查版本、健康、业务冒烟和失败重试。
5. [ ] 主动演练回滚：停止错误版本、恢复旧镜像/程序、确认数据库回退或前向修复策略与本项目真实存在的业务历史/审批数据不丢失。若不可安全回滚，阻止正式上线并上报。

## 关卡

目标服务器真实确认、备份恢复及发布/回滚有执行证据，技术总监认可；未有服务器权限应给执行计划，不能称预演成功。

真实运行与人工确认要区分；缺数据/缺权限/未实际执行不可判为通过。

**统一发布指纹（F06）**：从系统验收至上线评审、部署预演、正式上线以不可变 `release_fingerprint = Git Commit + 前端产物digest + 后端镜像digest + 数据库迁移文件checksum集合 + 配置基线摘要（不含密钥）` 关联证据与审批编号，另列实际环境版本。Tag仅展示用途，不替代 digest。任一构件、SQL或配置变化，旧证据不得自动沿用；先做影响分析，至少重跑受影响的业务验收、性能/安全及部署回滚预演，并重新审批。

- [ ] 恢复目标位于独立副本或实例，所有破坏性生产动作具有逐命令单独授权。
