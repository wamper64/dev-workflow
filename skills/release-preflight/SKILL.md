# 开发与测试环境部署预检

## 1. 职责与输入

此 Skill 是 `release-delivery` 内部的前置门禁，**不独立成为导航步骤，也不执行目标应用发布**。

只支持：开发环境首次上线、开发环境版本更新、测试环境首次上线、测试环境版本更新。先明确选定一个目标环境及其发布类型，不得以另一个环境的配置、端口、数据或测试证据代替。

输入：
- `docs/input/环境资料/` 中选定的开发或测试环境资料；`code/deploy/` 实际部署包与该环境已确认配置；
- 本次 Git Commit、前端构建/后端镜像 digest、数据库迁移文件 checksum、脱敏配置摘要及相关第三方连通资料；
- 已运行服务清单和目标数据状态；版本更新还需当前版本、数据/附件备份与变更清单；
- 本次环境检查与预演的明确授权，且不得假定可以直接执行发布。

## 2. 预检过程

1. **选环境**：只能是开发或测试。核验目标主机与该环境专属 Compose 项目名、目录、容器网络、宿主端口、卷、数据库与凭据注入；同机部署必须隔离，避免覆盖另一环境。
2. **判首次/更新**：首次应用上线要验证 S06 相关基础服务与依赖确实已就绪、预期初始化对象及启动入口；更新要核对旧→新版本、兼容、现存数据、变更和回退点，不得重跑会破坏数据的初始化。
3. **检查构件和权限**：记录发布指纹（Git Commit + 构建/镜像 digest + SQL checksum + 非密钥配置摘要）及操作授权；任何敏感信息只在受保护的私有配置中，不写到仓库。
4. **备份及回退**：根据真实数据风险准备数据/附件/配置备份。需要恢复试验时，只能在**隔离副本**或独立实例中执行；清理卷、覆盖数据库、危险迁移等必须在执行前取得**单独授权**，不得伤及同机其他环境。
5. **预演与核验**：在授权的隔离范围内验证本次首次安装或增量迁移、依赖连通、健康检查和回退路径。若脚本或回滚策略不可执行，则返回受阻，不宣称预演通过。
6. **交接关卡**：由选定环境负责人审核预检证据及阻断项；仅通过并获取**部署操作授权**，才能继续由 `release-delivery` 实际执行。

## 3. 正式产物

## 5. 两个维度的执行差别

| 目标环境 | 首次应用上线 | 已有版本更新 |
|---|---|---|
| 开发 | S06基础服务就绪、首次应用配置、启动入口和隔离校验 | 开发库备份/迁移兼容、旧版本及回退点 |
| 测试 | 测试专属配置、库/卷/账号隔离、测试入口就绪 | 测试数据保护、迁移、回归和恢复演练 |

**安全原则**：核对的环境必须与部署的环境一致；没有实际权限只生成待执行计划，不执行部署。Git 提交说明使用中文。
