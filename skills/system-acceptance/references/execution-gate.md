# 系统业务验收门禁

逐项依据**当前项目已确认PRD与实际可运行工程**执行；不将报价、审批、IoT或Agent案例自动推广为所有项目的必做功能。

- [ ] 按角色×核心业务场景建立PRD覆盖矩阵，逐场景记录主责模块、真实入口、输入、预期结果、异常分支和项目经理验收人。
- [ ] 在实际可执行入口开展端到端验证：既有Web页面、设备事件、定时触发、第三方回调或Agent操作，以真实业务触发途径为准。
- [ ] 核对跨模块组件协作、权威数据写入、重要状态/版本引用及可观察输出；只验收当前项目真实存在的链路。
- [ ] 对实际涉及的角色/租户/项目权限执行授权与越权测试，核查重复提交、失败恢复、重试、驳回或取消等适用异常分支。
- [ ] 真实收集步骤、执行账号、环境、请求/事件、界面/日志、数据库状态及必要第三方证据，不使用模拟结果冒充生产能力。
- [ ] 失败项定位责任模块并关联Bug，修复后按原场景和角色复测，保留第一次失败与最终证据。
- [ ] 项目经理逐场景确认真实结果；任一关键场景未测、受阻或存在阻断缺陷不得宣布系统验收完成。

## 放行与产物

输出 `docs/output/07-系统验收/业务场景覆盖矩阵.md`、`系统验收报告.md`、`缺陷闭环记录.md`（有缺陷需保留真实闭环，无缺陷注明无）。项目经理根据实际场景证据签收；缺少业务环境/权限则明确受阻，退回责任模块。
