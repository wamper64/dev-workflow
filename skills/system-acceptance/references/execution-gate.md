# 系统业务验收独立门禁

按**当前项目已确认的项目PRD与模块PRD**执行；IoT、Agent、审批、报表或报价只在当前项目存在时纳入。

- [ ] 交付模块及真实签收、环境、账号与版本信息可追溯；没有环境则报告受阻。
- [ ] 在 `系统验收报告.md` 内建立角色×场景覆盖矩阵，包含PRD来源、主责/协作模块、真实入口、输入、预期、实际、证据和签收人。
- [ ] 真实跨模块业务主链逐个执行，核对权威状态、版本引用与最终业务结果；已有模拟仅可作为补充证据。
- [ ] 按实际业务覆盖权限/越权、重复提交及失败/重试/驳回/取消的适用异常链，注明不适用的依据。
- [ ] 把每项失败/受阻与责任模块、原始证据、修复措施及同场景复测直接记录到同一报告正文。
- [ ] 对已完成模块的高风险跨模块链路按真实变更范围回归。
- [ ] 项目经理在同一报告签收；关键场景未测、失败、受阻或无证据不得放行正式项目业务验收。

## 唯一正式产物

`docs/output/07-系统验收/系统验收报告.md`。

不得另建 `业务场景覆盖矩阵.md`、`缺陷闭环记录.md`，也不得用“已生成模板”冒充真实执行完成。非功能系统质量验收由后续 `release-readiness` 完成。
