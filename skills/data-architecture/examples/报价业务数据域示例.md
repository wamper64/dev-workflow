# 报价系统数据域（总体层级示例）

| 数据域 | 主要对象 | 业务所有权 | 关联边界 |
|---|---|---|---|
| 报价项目 | 项目、客户和项目状态 | 项目业务服务 | 参数、计算单和报价用项目ID关联 |
| 需求解析 | 原始文件、候选参数、人工确认参数版本 | 需求核对服务 | AI候选不能覆盖人工确认版本 |
| 模板和词典 | 字段字典、同义词、报价模板版本 | 规则配置服务 | 修改模板/字典不得静默重写已审批报价 |
| 历史计算单 | 计算单、匹配候选与复用结果 | 计算单服务 | 引用计算依据及对应需求版本 |
| 报价审批 | 报价版本、审批任务、审批历史 | 报价/审批权威服务 | 不因重新提交删除原审批链 |
| 交付和归档 | 客户输出、归档与业务追溯 | 归档服务 | 按基线中已批准年限保存引用链 |

## 单库判断示例

在基线批准的单机/数据量范围内，如业务域并没有独立合规、负载隔离或团队自治需求，可以先选一个MySQL实例中的逻辑业务模块；这是**候选方案**，不能绕过技术总监的资源评审。

文件大对象是否保存在数据库之外，需要结合备份可恢复目标、附件增长量、当前服务器和第三方存储条件具体裁定。本阶段不生成具体字段/DDL。
