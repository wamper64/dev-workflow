# S05 三核心可执行契约

> 输出以**表、字段、键、关系**为中心。组件/协议/时序＝S04，接口/方法/参数/报文＝S09，均只引用结论、不重画。**章节要求编号**；规则/条目本身不加代号（不写 A1/①②/R01）。

## 核心一｜整体数据规则

按 `references/rule-catalog.md` 的固定清单逐条填「本项目结论」：

- 一条规则一行，结论 **1–2 句**写重点，只写本项目采用的**结论值**；规则用名称指代，不编号。
- 不写来源、依据、检查方式列；证据留评审时给。
- 未触发规则写「不适用」，不写空壳。每条给冻结级别 A/B/C。

**固定命名约定**：`tb_`＝主数据/配置/实时快照，`tr_`＝关系表，`tl_`＝流水/日志/历史；新增业务表落到其中一个前缀；`sys_*` 等框架和第三方既有表沿用原名和原有合法键模型。

## 核心二｜关键数据业务流程

### 1. 数据域划分——用一张图

画一张 Mermaid 图：**节点＝数据域，边＝域间关联，边上标连接键与方向**（如 `平台域 --tenant_id--> 设备域`）。图下**一句话**写依据与作用，不写成段文字。

- **依据**：一个域＝**一族同生命周期的核心对象**，以「**权威写方 / 保留边界 / 一致性边界**」判定。
- **关系表（`tr_`）不单独成域**：归入它服务的对象族所在域（如用户-电站权限位归身份与权限域）。
- **框架对象族与其业务扩展表服务同一对象族时同域**：域内按表标注写方（如身份与权限域中 `sys_*` 归框架、`tr_*` 归业务域）。
- **域数保持精简**，能合则合；只有对象族、保留或写方边界确实不同才独立成域。
- **作用**：归口（一对象一 Owner）、边界（域内强一致/跨域最终一致）、落位（存储、分库分表、保留策略的单元）。

### 2. 逐域以表为主体画流程

- **流程图节点直接写表名并在括号里给一句话释义**（如 `tb_gateway（设备档案）`）。**不要**另起一张「流程图用到的表」清单——释义就在用到处。
- 每条流程配**表动作矩阵**：每行一步，列为 涉及表（写/读）、字段/状态变化、写入 Owner、一致性/异常。
- **状态机/控制类流程同样按表画**：状态迁移处标注**写入了哪张表**（不能出现只有状态、看不出表的流程）。
- 只讲数据怎么产生/变化/归档。不画组件、协议、报文、类、方法——那分别是 S04 与 S09。

## 第三章｜分库分表设计（独立成章）

判定是否分库/分表/分区，给出证据与**量化触发条件**。**需要时给出完整设计**，写到可直接落地：

- **分的方式**：水平/垂直、范围/哈希/一致性哈希；分几片。
- **分片键**：选哪列、为什么；分片表清单（哪些表分、按什么键）。
- **表结构**：每个分片表的物理形态（分片键列、唯一键/主键须含分片键、表名后缀规则）。
- **路由**：路由键来源与方式（如按会话 `tenant_id`）。
- **全局唯一 ID**、**跨片查询与聚合**、**扩容再平衡**、**与主从/备份恢复的关系**。

不需要时写「暂不分库分表」＋触发条件；高吞吐时序表可先按时间做 MySQL RANGE **分区**（同样写清分区列与表结构变化）。

## 核心三｜核心表、核心字段与关联关系

**选表条件**（至少符合其一）：跨模块共享身份/关键引用；主业务闭环核心状态/版本；高成本不可逆历史/审批/计量事实；关键外部数据关联标识。一个页面不必一张表，也不因多 Worker 拆多库。框架已有表标「复用」。

交付三件，顺序固定：

1. **核心表清单**：表名（新增表贴 `tb_/tr_/tl_` 前缀，已有表保留原名）、业务对象、已存在/新建、业务身份键、数据域/Owner、保留与删除边界。
2. **核心字段**（逐表）：字段名、类型（含单位/精度）、业务含义、必填/空值、唯一/状态/版本/引用约束。写实际字段名，不写 `id/status` 之类空泛名；不写整表 DDL、不铺开非核心字段与完整索引。
3. **核心 ER 图与关系契约**：用**分域小图**（建议每域 2~6 个表，实际1表或超过6表也按真实关联绘制）一张 Mermaid `erDiagram`），再配一张关系契约表；每条关系写成 `主体表.字段 —(基数)→ 被引用表.字段` 并说明删除/历史约束。**不把所有表挤进一张大图**；跨库/跨模块/高吞吐追加表用**逻辑引用**，不强制物理外键。

## S05 与 S09/S12 深度对照

| 项目 | S05 必须定 | S09 在 S05 上细化 | S12 实际执行 |
|---|---|---|---|
| 核心表 | 名称、对象、Owner、共享角色与核心关系 | 补完整非核心字段与模块内关联 | 版本化建表/变更脚本 |
| 核心字段 | 名称、必要类型/精度、业务约束、状态/版本/关键引用 | 默认值、完整字段字典、实现级约束/索引 | SQL 与实体代码 |
| 辅助表 | 仅确定必要全局关系原则，不穷举 | 表、字段、索引与生命周期 | 迁移与验证 |
| 数据流程 | 核心数据生命周期、一致性与追溯 | 每接口动作/事务及异常处理 | 自动/人工真实验证 |
| 分库分表 | 分的方式/分片键/表结构/路由/ID/扩容（需要时） | 分片中间件配置、跨片查询实现 | 分片迁移与验证 |
| Schema/Owner 变动 | 由 S04/S05 审定 | 不得私改已冻结契约 | 不得绕过评审 |
