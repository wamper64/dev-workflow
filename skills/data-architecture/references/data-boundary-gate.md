# S05 数据库总体设计：两轮质量关卡

## 第一轮｜业务与三核心完整性（项目经理+技术负责人）

- [ ] 来源真实：已读全量相关`docs/input/`、S03、已审定S04关键业务链、存储/状态Owner、真实`code/`已有表与框架能力（不可读的明确记录）。
- [ ] 核心一（整体规则）：有可落地的统一身份、业务唯一、关联、存储、精度/时间、状态版本、Owner、删除历史、权限、备份迁移规则；项目专项仅按实际触发。
- [ ] 核心二（关键数据业务流程）：已按PRD/S04覆盖有不同数据语义的主流程、状态变化、外部接入及关键失败路径；每条有图+数据动作矩阵，并说明来源→存储→状态/版本→引用→终态/追溯。
- [ ] 核心三（数据骨架）：真实核心表、核心字段的名称与必要类型/业务含义/唯一性/关系已经明确，包含跨模块共享身份和必要状态/版本；核心ER图基数及引用字段与表格一致。
- [ ] 双向追溯：规则→核心数据流程→核心表/字段→下游模块；不存在关键流程无落表、核心身份无人维护、重复数据权威、无依据多建表。
- [ ] 不偷偷扩大范围：S05虽需具体全局核心字段，但不要求全部模块非核心字段、辅助表或DDL；不把菜单数自动变为表数/库数。

## 第二轮｜可实施与上下游一致性（技术总监+开发负责人）

- [ ] 跨模块选取至少一条真实链路，现场沿**规则→数据产生→状态/版本变化→核心表/字段→关联引用→数据Owner/存储→失败恢复→S09接管细节**逐项核对。
- [ ] 核心表复用真实既有代码/公共框架；未观察到的既有DDL不得假称已确认；新增字段与数据库版本一致。
- [ ] 关键全局表身份/版本/精度的定义和S04已批准的状态Owner、组件通信无冲突；有冲突先返回S04，不在S05私自改变运行组件。
- [ ] 单库/多库/分片、缓存/附件权威、容量/备份恢复依据实测或有明示假设；无数据支持写“暂不分库分表+复评指标”，不写空泛“预留分片”。
- [ ] 关键项目约束已落实，历史记录和引用不会因删除或重算静默失效。
- [ ] A级跨模块核心键/权威/状态版本锁定、B级兼容规则、C级模块字段自由扩展界线明确；S09发生A级变更必须先重审S05，必要时重审S04。
- [ ] 两轮审核每项有图/表/代码或已批准文档证据；缺少决定性输入或重大矛盾应“退回/阻塞”，不能声明全局数据骨架完成。

输出`docs/output/03-数据库总体/数据库设计审核.md`应记录审核角色、结果、具体未过项、需补证据及返回路径。演示样例不得作为真实项目审批证据。
