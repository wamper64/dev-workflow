# 数据库总体设计检查清单

- [ ] 数据域来自确认PRD业务闭环，而非直接把菜单当数据域
- [ ] 业务状态/业务版本只有明确的最终权威方，跨域引用有方向
- [ ] “重解析”“重新匹配”“审批驳回重提”不会静默覆盖已确认版本
- [ ] 数据库产品、服务器CPU/内存/磁盘与基线继承一致
- [ ] 单库/分库分表有基于数据量、访问、隔离或权限的明确证据
- [ ] 数据库、附件、普通缓存、历史与审计数据有不同责任和备份覆盖
- [ ] 保留年限起算点与报价、参数、计算依据、审计引用链一致
- [ ] 数据容量基于当前存量、年增量和保存年限，缺少指标先推荐并提问
- [ ] 明确哪些属于后续模块表结构设计，未偷偷输出字段/建表DDL
- [ ] 技术总监审核通过才能作为模块库表设计的上游约束

如没有真实分片需求，明确写“暂不分库分表”及扩展的触发指标，而不是模糊地写“预留分库分表能力”。
