# 数据库设计规则清单（逐条填「本项目结论」）

> 用法：这是数据库总体设计的**固定规则表**。一条规则一行，结论 1–2 句写重点，只写**本项目采用的结论**；不写来源、依据、检查方式列。
> **不使用编号**：规则用名称指代即可。未触发的规则写「不适用」；证据留评审时给，不写进设计正文。每条给冻结级别：**A** 跨模块核心键/权威/状态版本（变更需技术总监审批并同步 S04/S09）；**B** 全局命名/精度/隔离/迁移规则；**C** 模块局部。

## 命名与键

- **命名规范**：表与字段用小写 snake_case 英文、见名知义、避开 SQL 保留字；索引 `uk_`＝唯一、`idx_`＝普通。— 结论写本项目采用的命名与索引前缀。
- **表名前缀**：`tb_`＝主数据/配置/实时快照，`tr_`＝关系表，`tl_`＝流水/日志/历史；仅新建业务表默认遵守，框架/第三方已有表保留名字和键模型。— 结论区分“新增/复用”。
- **主键**：新建普通业务表默认使用 bigint 代理主键；已有框架表、外部系统映射、分区/分片表可沿用或设计复合键，并给出唯一性/分区条件与兼容原因。— 写主键生成方式（自增/雪花）。
- **业务唯一键**：业务身份单独建唯一索引（`uk_`），唯一性由数据库兜底。— 写设备 IMEI、编码、卡号等唯一范围。
- **外键与引用**：跨库、跨模块、高吞吐追加表用**逻辑引用**（不建物理外键）并给引用列建索引；库内强一致关系可建物理外键。— 写引用策略。
- **数据类型与字符集**：选最小够用类型；计量/金额用 decimal 定精度；字符集 utf8mb4。— 写关键列类型口径。

## 数据质量与时间

- **时间与时区**：系统规范时间以批准时区/UTC存储，需跨时区溯源时保存事件来源时间与 offset/timezone；区分**事件时间**（设备/业务发生）与**记录时间**（入库）；表含 create_time/update_time。— 写时区与两类时间列。
- **空值与默认**：缺失写 NULL，不用无意义默认值掩盖缺失；0 与 NULL 语义分开（如全 0＝查询）。— 写关键空值语义。
- **计量与精度**：写清单位（mA/℃/M）与精度、舍入。— 列本项目计量口径。
- **状态与枚举**：状态用 tinyint/短串，与字典一致，列注释写全取值。— 列核心枚举。

## 生命周期与一致性

- **逻辑删除**：业务实体逻辑删除（`is_deleted`/`del_flag`），不物理删除；**逻辑删除须与唯一约束相容**；不得将布尔删除标志直接拼进唯一键作为普遍解决方案（第二轮重建再删除会冲突）。按具体数据库版本选择有效行唯一索引/生成列，或删除时归档业务键/写唯一墓碑键；验证两轮创建→删除→重建→删除。— 写删除策略、例外与唯一键相容方式。
- **不可变历史**：审批/计量/授权/指令等不可逆事实追加写、不覆盖。— 列不可变表。
- **审计字段**：关键表带 create_by/create_time/update_by/update_time。— 写审计范围。
- **版本与归档**：写清每类数据的保留期与归档/清理策略。
- **写入 Owner**：一个对象只有一个权威写方。— 列每类表的读写方。
- **事务与最终一致**：单库内核心状态＋审计同事务；跨库/异步用最终一致＋补偿。— 写一致性边界。
- **幂等与并发**：外部/异步写入用幂等键（唯一约束）；并发更新用版本列或唯一键。— 列幂等键。
- **索引**：为查询/过滤/排序列建索引，复合索引最左前缀，避免过度索引。— 列核心索引（详细信息留 S09）。

## 隔离、存储与演进

- **多租户/权限隔离**：业务表带租户键并建索引；隔离在应用层强制。— 写隔离键与规则。
- **敏感字段保护**：密码/密钥加密或引用化（`_ref`），不入库明文。— 写敏感列处理。
- **容量与保留**：每类数据留量与容量闭合到可用磁盘。— 写容量结论与假设。
- **存储分层与拆分**：默认单库；仅按证据分库；给出量化触发条件。**一旦判定需要分库/分表/分区，必须给出完整分库分表设计**（分片对象与分片键、分片规则、路由方式、全局唯一 ID、跨片查询与聚合、扩容再平衡、与主从/备份恢复的关系）。— 写采用与否 + 触发条件；需要则写完整设计。
- **备份与恢复**：备份覆盖所有库，明确 RPO/RTO、离机副本与恢复顺序。
- **迁移与演进**：结构变更走增量脚本，前向兼容，不改已部署结构。
- **注释**：表与字段写业务注释；枚举列注释写全取值。
- **大字段与附件外置**：大文本/二进制不入业务表主列，附件走对象存储并在表内存 `_ref` 与元数据，库内只留必要摘要。— 写外置策略。
- **明细/快照/聚合的界线**：区分实时快照（当前值，随业务更新）、明细与历史（追加写）、聚合/统计（可由明细重算）；聚合表必须可重算，不成为唯一权威。— 写本项目三层各自的表与存储。
