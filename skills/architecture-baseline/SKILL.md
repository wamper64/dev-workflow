# 整体架构设计

## 1. 职责与范围

本技能负责完成「整体架构设计」，为下一个研发步骤提供可审核产物。输入资料位于 `docs/input/`，产物统一位于 `docs/output/`。后端在 `code/guiwu_ruoyi/` 现有框架上扩展，前端必须沿用 `code/fld/` 原型的布局、样式与组件。

## 2. 输入

- `docs/output/01-项目基线/项目基线.md`
- `docs/input/工程资料/`
- `code/fld/`
- `code/guiwu_ruoyi/`
- `docs/input/对接资料/`

## 3. 工作步骤

1. 以项目基线为硬边界，确定系统运行单元、责任归属、认证授权方式和既有代码复用范围。
2. 画系统组件和部署拓扑，明确前端原型、若依、存储、第三方服务间的交互与失败行为。
3. 对未裁决的高成本技术选择提出方案、取舍和推荐，由技术总监确认。
4. 核对报价主业务路径、权限与第三方约束；不通过则修改架构设计。

## 4. 异常与审核

不要展开业务模块的Controller/字段/DDL。

审核要求：技术总监评审运行架构、跨服务通信、全局认证及对接方案；不通过则修正设计。

不足以得出真实结论时提出关键问题和有依据的推荐。未经确认不得将推荐写成最终约束；未实际操作不得宣称已完成。涉及 Git 提交使用中文说明。

## 5. 输出

- `docs/output/02-整体架构/整体架构设计.md`
- `docs/output/02-整体架构/架构评审记录.md`
- `按需：docs/adr/架构决策.md`
