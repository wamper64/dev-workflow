# 整体架构设计检查关卡

| 核验主题 | 具体必须检查 | 不通过处理 |
|---|---|---|
| 继承约束 | 技术版本、目标机CPU/内存/磁盘、并发与响应目标不被隐式修改 | 提交基线变更，暂缓定稿 |
| 前端保真 | 使用 code/fld 已有原型、路由、UI组件，禁止重做视觉体系 | 改回在原型上扩展的方案 |
| 后端复用 | 若依认证、菜单、权限、日志和数据访问能力真实可复用，而非重复造轮子 | 调整服务/模块划分 |
| 运行单元 | 各进程存在理由明确；不能为了分层无故拆微服务 | 合并到合理单元 |
| 数据责任 | 报价、参数、审批、附件唯一写入责任；跨单元一致性策略清楚 | 补责任矩阵 |
| 接口 | 跨单元调用协议、超时、错误传播、幂等、调用方鉴权、长任务状态明确 | 补交互图 |
| 报价业务链 | 正常流程、退回与重提均有执行路径，不跳过人工确认 | 补场景覆盖 |
| 部署预算 | 资源预算及端口网络与目标环境闭合；有备份和恢复路径 | 减组件或提扩容申请 |
| 可观测性 | 能定位失败单元/任务、记录审计关联ID、健康探针有范围 | 增加边界契约 |
| 评审 | 技术总监清楚通过/退回及实际证据 | 不得写已审核 |

输出真实结果而不是泛泛“支持高并发”。不重复项目基线所有表格，但要引用并核验其资源上限。
