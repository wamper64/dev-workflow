# 整体架构适用性：统一检查、专项按条件启用

## 所有项目必须核验十项

系统边界、技术选型与既有代码复用、前后端工程结构、逻辑组件职责、跨组件交互、数据Owner/一致性、安全权限、容量可靠性、部署运维恢复、A/B/C架构冻结与演进。

上述是检查维度，不意味着每个项目必须新增对应运行单元。根据真实PRD、工程、环境、对接文件填“启用/不适用/待裁决”，不凭公司业务类型套架构。

| 专项 | 触发条件 | 必须决定的内容 | 不得默认 |
|---|---|---|---|
| Web/业务管理 | 管理页面、业务审批、文件、长任务 | 现有UI/框架复用、权限/审批Owner；存在长任务时确定异步和状态 | 审批引擎、微服务 |
| 工业IoT | 设备、现场网关、物联网平台、摄像头 | 设备/测点标识、协议解析Owner、采样/上报与时间戳、去重补报、告警、设备命令与回执及设备安全 | MQTT、时序库、独立Broker |
| AI Agent + Web | 模型、Agent、知识检索、工具调用、人工确认 | 模型密钥/额度、工具权限、业务与执行状态Owner、HITL/恢复、知识权威、AI候选与正式业务结果区分 | AgentScope、RAGFlow、六Worker |
| 第三方集成 | ERP/MES/MOM、外部Worker、第三方数据库/API/iframe/文件 | 协议、鉴权网络、数据权威、同步周期/版本、错误重试、受理与完成的边界 | 回调可用、真实接口已通 |

专项可叠加；启用后必须出现在同一张系统全景图、关系总表和重要时序中；没有触发证据时标不适用并说明理由，不生成无意义章节。缺失且影响顶层的资料由本Skill内部Grill裁决，未确认不能视为已冻结。
