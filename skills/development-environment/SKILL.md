# 开发环境实际部署与验收

## 1. 工作目标与输入

不是提出环境建议，而是实际验证本机能运行现有前后端和必要数据库/中间件，为每轮模块开发提供可复现的开发环境。

- `docs/output/01-项目基线/项目基线.md`
- `docs/output/02-整体架构/整体架构设计.md`
- `docs/output/03-数据库总体/数据库总体设计.md`
- `code/fld/`
- `code/guiwu_ruoyi/`

## 2. 具体操作

1. 读取项目基线的实际技术及版本、整体架构运行单元和数据库总体选型，列出真正需要的MySQL/Redis/MQ等，按需探测本机已有服务、容器、运行目录和端口；禁止将某个人的Windows目录作为前置条件。
2. 检测现有数据库/容器可否复用：版本/绑定IP/端口/持久卷/空间、已有业务库是否被占用、凭据从安全配置读取（不打印密码）。
3. 仅对缺失依赖生成合适的Docker Compose或本机启动配置；配置数据库、服务健康检查、日志轮转与必要初始化，保留可重新运行的命令。
4. 在code/guiwu_ruoyi上实际启动后端、执行健康/API请求并验证MySQL连接；在code/fld上启动前端并验证原有路由、API代理、跨域及登录流程，必要时给出修复依据。
5. 输出系统版本、命令、退出码、HTTP响应与关键日志；未实际执行时写“待执行”，不得宣称联通成功。

## 3. 审核与失败路径

**关卡**：至少现有前后端、必需数据库和真实API联通已获得本次运行证据；第三方环境受限须记录并单列，而非当模拟成功。

输入资料并不自动等于事实已确认，实际程序运行没有命令与输出不能填“已通过”；所有技术建议均以本项目已确认基线和PRD为准。
