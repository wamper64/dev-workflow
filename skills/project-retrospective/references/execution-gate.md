# 项目全流程复盘与Skill改进的核查标准

1. [ ] 按工作阶段分析哪些设计决策迟迟没有澄清，是否应前置Grill或精简重复产物；区分项目PRD不清、整体架构不清、模块细节不清三种原因。
2. [ ] 统计可证实的返工次数、人工测试发现Bug数、重复代码评审问题和部署阻塞，不将未经统计的AI提效比例写成事实。
3. [ ] 将Bug按原因归类：遗漏业务场景、原型被错误改造、接口契约错误、第三方信息缺失、权限/状态不变量被破坏、CI无反馈环。
4. [ ] 已有Matt retro用于会话层的模型/Agent/工具导航问题；项目级复盘改进整体工作步骤、人员审核点和产物粒度，避免重复写会话总结。
5. [ ] 每项改进给出对象、拟改动作、验证方法、预计影响的下一项目阶段和责任人，交技术总监确认后再修改Skill与标准Workflow。

## 关卡

每个根因都能追到真实证据，每个提案有可检验动作；未经确认不自动修改既有签署基线或产品代码。

真实运行与人工确认要区分；缺数据/缺权限/未实际执行不可判为通过。
