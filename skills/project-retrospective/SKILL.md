# 项目全流程复盘与Skill改进

## 1. 职责和输入

复盘首次项目建设从基线、Grill、架构、模块、开发到部署的真实返工、沟通与质量证据，转化为经过审核的工作流和Skill调整，不重复Matt编码会话retro。

- `各阶段的审核记录与ADR`
- `Specs、Tickets、Bug、人工测试、上线记录`
- `Matt retro实际会话输出（有则引用）`

## 2. 执行与验证

1. 按工作阶段分析哪些设计决策迟迟没有澄清，是否应前置Grill或精简重复产物；区分项目PRD不清、整体架构不清、模块细节不清三种原因。
2. 统计可证实的返工次数、人工测试发现Bug数、重复代码评审问题和部署阻塞，不将未经统计的AI提效比例写成事实。
3. 将Bug按原因归类：遗漏业务场景、原型被错误改造、接口契约错误、第三方信息缺失、权限/状态不变量被破坏、CI无反馈环。
4. 已有Matt retro用于会话层的模型/Agent/工具导航问题；项目级复盘改进整体工作步骤、人员审核点和产物粒度，避免重复写会话总结。
5. 每项改进给出对象、拟改动作、验证方法、预计影响的下一项目阶段和责任人，交技术总监确认后再修改Skill与标准Workflow。

## 3. 审核关卡与失败后回退

每个根因都能追到真实证据，每个提案有可检验动作；未经确认不自动修改既有签署基线或产品代码。

每一项状态必须基于实际文件、真实测试记录、当前代码及环境；没有可执行环境或缺少授权时必须给出阻塞结论，不得编造完成记录。涉及Git提交均使用中文提交说明。

## 跨阶段返工复盘（不同于Matt retro）

```mermaid
flowchart LR
  A[Grill/设计/开发/测试/上线证据] --> B[返工发生在哪一关]
  B --> C[根因归类:漏问/漏设计/实现缺陷/环境证据不足]
  C --> D[具体改哪一个Skill或质量门禁]

```

对于每个反复出现的失败用 `发生阶段 | 相关文件/会话/缺陷证据 | 当时应该识别的前置条件 | 未识别原因 | 拟调整Skill/工作流 | 如何验证 | 审核人` 表达；不要把推测的AI提效时间写成实际数据。Matt `retro` 保持AI编码会话层面的工具/Agent改进；本Skill关注跨阶段的项目交付效率、Grill决策前置和验收门禁。输出 `docs/output/09-复盘/项目研发复盘.md` 与 `Skill和流程改进建议.md`。
