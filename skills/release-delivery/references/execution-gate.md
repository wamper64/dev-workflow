# 开发/测试/正式环境应用首次上线与版本更新门禁

1. [ ] 明确本次目标环境和类型（首次应用上线/已有版本更新），核对环境专属配置、旧版本与本次发布指纹，防止误覆盖其他环境。
2. [ ] 有对应环境与操作的明确授权、实际预演和备份恢复路径。**正式环境额外需要 S16 业务验收、S17 非功能系统验收与技术总监上线许可。**
3. [ ] 首次应用上线核实基础组件、首建依赖及业务入口；版本更新核对兼容、DB迁移和必要回归，按批准顺序执行。
4. [ ] 记录执行人、时间、实际命令、退出码、构建/镜像/SQL摘要及健康结果。
5. [ ] 根据当前**项目PRD实际存在的核心业务场景**执行环境冒烟；不得硬写报价、审批或其他项目特有功能。
6. [ ] 观察资源、日志、数据库、队列及第三方接口；出现阻断执行批准的回滚/前向修复方案，未经授权不得恢复生产权威库。
7. [ ] 交付版本、配置/回滚与运维资料。开发/测试成功不能作为正式生产上线证明，预演也不能替代实际部署。
