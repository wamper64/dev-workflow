# 模块拆分

> 类型：自建  
> 参考：bmad-code-org/BMAD-METHOD / README.md  
> 来源：[GitHub 源文件](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/README.md)  
> 本文是针对项目场景的原创实现说明，并非上游 Skill 原文。

## 一、职责与边界

本 Skill 只负责「模块拆分」，从确定的输入形成可审核输出，不越权替代其他步骤。  
项目原型基线是 `code/fld/`；后端框架是 `code/guiwu_ruoyi/`。PRD 位于 `docs/input/需求资料/`，其他可选输入位于 `docs/input/工程资料/`、`docs/input/环境资料/`、`docs/input/对接资料/`。不重做已确认PRD，不独立设计另一套前端视觉与交互体系。Git提交说明使用中文。

## 二、触发条件

当前研发工作流执行到「模块拆分」，且存在所需输入或已记录的阻塞项时调用。无权访问或无法验证时明确给出阻塞状态，不虚构结果。

## 三、输入

- `docs/input/需求资料/PRD（包含现有页面功能信息）`
- `docs/output/01-项目基线/项目基线.md`
- `docs/output/02-整体架构/整体架构设计.md`
- `docs/output/03-数据库总体/数据库总体设计.md`
- `docs/output/04-开发环境/开发环境部署与验收.md`

## 四、执行流程

```mermaid
flowchart TD
    N0["引用PRD模块能力"]
    N1["按职责与数据域划分"]
    N2["依赖排序"]
    N3["双角色审核"]
    N0 --> N1
    N1 --> N2
    N2 --> N3
    N3 --> G{"验收条件满足？"}
    G -- 否 --> R["记录问题 / 退回修正"]
    R --> N0
    G -- 是 --> OK["提交可追溯产物"]
```

### 执行准则

1. **引用PRD模块能力**：读取对应上下文和实际证据，检查与前序项目基线的关系，记录决定和异常。
2. **按职责与数据域划分**：读取对应上下文和实际证据，检查与前序项目基线的关系，记录决定和异常。
3. **依赖排序**：读取对应上下文和实际证据，检查与前序项目基线的关系，记录决定和异常。
4. **双角色审核**：读取对应上下文和实际证据，检查与前序项目基线的关系，记录决定和异常。




按PRD中的业务场景、责任和数据域拆模块，不按菜单机械划分，不先确定Spec份数。



## 五、输出

- `docs/output/05-模块拆分/项目模块清单.md`
- `docs/output/05-模块拆分/模块依赖关系.md`
- `docs/output/05-模块拆分/模块拆分审核.md`

## 六、验收与中止条件

项目经理确认业务覆盖和功能归属，技术总监确认模块依赖与架构一致；不预设Spec数量。

若输入文档不支持技术结论、第三方接口未确认、实测环境不可达，应输出待确认项并中止受阻部分。产出必须与本项目的PRD、源码和工程基线一致。
