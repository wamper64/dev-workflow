# 模块拆分

## 1. 职责与范围

本技能负责完成「模块拆分」，为下一个研发步骤提供可审核产物。输入资料位于 `docs/input/`，产物统一位于 `docs/output/`。后端在 `code/guiwu_ruoyi/` 现有框架上扩展，前端必须沿用 `code/fld/` 原型的布局、样式与组件。

## 2. 输入

- `docs/input/需求资料/PRD（包含现有页面功能信息）`
- `docs/output/01-项目基线/项目基线.md`
- `docs/output/02-整体架构/整体架构设计.md`
- `docs/output/03-数据库总体/数据库总体设计.md`
- `docs/output/04-开发环境/开发环境部署与验收.md`

## 3. 工作步骤

1. 直接读取PRD中已有的页面/场景清单，无需重新绘制完整页面映射。
2. 按业务闭环、领域责任、共享数据和既有代码位置划分实际模块。
3. 输出模块依赖、前置契约与可开发顺序，解释调整原有13个候选模块的理由。
4. 项目经理审核业务覆盖，技术总监审核依赖与架构边界，不通过回退修改。

## 4. 异常与审核

一个菜单不必等于一个模块，不预设8个Spec。

审核要求：项目经理确认业务覆盖和功能归属，技术总监确认模块依赖与架构一致；不预设Spec数量。

不足以得出真实结论时提出关键问题和有依据的推荐。未经确认不得将推荐写成最终约束；未实际操作不得宣称已完成。涉及 Git 提交使用中文说明。

## 5. 输出

- `docs/output/05-模块拆分/项目模块清单.md`
- `docs/output/05-模块拆分/模块依赖关系.md`
- `docs/output/05-模块拆分/模块拆分审核.md`
