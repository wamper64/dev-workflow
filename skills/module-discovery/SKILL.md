# 项目模块拆分

## 前提和输入

读取 `docs/input/需求资料/` 已确认项目/模块PRD（已有页面映射不要重做）、`docs/output/01-项目基线/`、`docs/output/02-整体架构/`、`docs/output/03-数据库总体/`、`docs/output/04-开发环境/`。观察 `code/fld/` 原型路由和 `code/guiwu_ruoyi/` 业务扩展点时只核对归属，不做代码质量审查。

## 业务分组

1. **从能力到模块**：先读取PRD中系统主流程、核心业务场景、角色以及页面清单；定义边界稳定、可独立测试与验收的一组业务能力。一个模块可以覆盖多个页面；一个跨业务流程页面可以调用多个模块。
2. **所有权分析**：按总体数据域、业务状态主责、审批/版本责任和权限边界划分。业务对象由一个模块作权威修改；可复用查询服务不自动变成独立服务。
3. **依赖图**：识别模块需要的前置项目ID、字典版本、模板、计算单、人工确认参数与角色权限，区分“必须先交付的模块”和“预先约定接口即可并行”的依赖。
4. **映射既有工程**：为各模块注明使用现有`code/fld/`页面或组件、在若依现有哪个业务包/模块扩展；禁止输出“建议重建一个新的Vue前端”。
5. **业务覆盖校验**：反向从PRD逐个场景查其业务模块归属，重点核对登录、报价完整主链、审批驳回/重提、归档、报表、审计。对“遗漏、重复、互相矛盾”执行补、删、改；不为了凑数量产生空模块。
6. **人工评审**：项目经理确认业务完整性与模块名称；技术总监确认数据域和依赖图的一致性。未通过继续调整；不自动为全项目模块同时生成Spec。
