# 模块拆分审核标准

| 评审 | 必须做到 |
|---|---|
| 业务覆盖 | PRD中的每个角色×核心场景可找到主责任模块；不以菜单数量推断模块数 |
| 边界 | 一个重要业务对象只有明确写入主责；共享字典/权限不被各模块复制 |
| 依赖 | 前置条件有明确“已交付/接口契约就绪/可并行”的标志 |
| 可验收 | 每个模块有真实可走通的业务场景，非按文件夹机械拆分 |
| 复用 | 指明对应 code/fld 原型页面和若依复用点，不替换原有视觉 |
| 数据库 | 继承总体数据域，不把模块拆分等同于分库分表 |
| 范围 | PRD已确认项不丢；未确认需求不偷偷加模块 |
| 人审 | 项目经理验收业务覆盖，技术总监审查耦合边界和依赖 |

不需要在这一步输出业务表字段、API明细、每个模块的完整Spec和Tickets。
