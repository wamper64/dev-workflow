# 模块实现与人工测试用例准备

## 1. 目标与边界

这是 **Matt `implement-spec` 的工作流扩展**，不是直接照搬原版，也不是重造第二套TDD/代码审查。正式步骤包含两段：

1. **调用原版执行**：显式调用 `skills/implement-spec/SKILL.md`，完整遵循其Spec/Tickets依赖图、integration branch、各Ticket子Agent调用`tdd`、合并、最终统一调用`code-review`和清理工作树的流程。
2. **原版结束后的追加动作**：使用确认的需求基线与本轮已运行的测试证据识别AI不能可靠验证的场景，生成**待人工执行的测试单**。不在这里冒充人工操作，不再次发起已经完成的TDD或Review。

无可运行环境/原版未完成/Review未通过时，不能宣称实现完成；将尚未可验证的场景标为受阻或待人工执行，保留确切原因。用户开始此步骤时即明确授权调用官方 `implement-spec`；若运行平台不支持Skill调用，必须告知限制，不得假装已经运行过原版。

## 2. 实际输入

- `docs/input/需求资料/`：**已确认需求基线**、项目/模块PRD、角色×核心业务场景及已有原型（存在才读）。
- `.scratch/<模块>/spec.md` 与 `.scratch/<模块>/issues/NN-*.md`，或实际配置的Issue Tracker。
- `docs/output/06-模块迭代/<模块>/模块详细设计.md`、迁移设计草案、本轮计划。
- `docs/output/01-项目基线/项目基线.md`、已批准整体架构组件与交互、数据库总体。
- `code/` 下当前项目实际代码、现有自动化/浏览器测试设施和可复用组件。
- 必要的真实对接及开发环境。账号/凭据不得写入输出文档。

## 3. 执行顺序

### 3.1 原版实现及代码评审

1. 检查Spec、Ticket依赖图和Issue Tracker是否就绪；不就绪应返回前一步，不能自创实现计划代替。
2. **调用 Matt 原版 `implement-spec`**，由其自行创建集成分支、安排Ticket与TDD、合并、执行最后的 `code-review`（Standards和Spec两个审查轴）、修复问题并收尾。**不要为每个Ticket另设独立Review，也不要额外重复同一批自动测试。**
3. 核查真实完成证据：集成分支/提交、已解决Tickets、实际测试命令/退出结果、代码审查结果、受阻接口与未经实际执行的检查项。只引用已存在证据，不凭总结语句推定全部通过。
4. 开发中数据库迁移脚本如与模块迁移设计草案不同，先依据真实SQL反向修订草案/详细设计并申请必要审核；不能为保持草案一致而掩盖真实变更。
5. 既有页面/组件需要原型保真时，已有可运行浏览器和基线截图则验证；没有工具或无法到达真实状态，应登记到人工测试筛选中，不宣称视觉已通过。

### 3.2 依据自动化覆盖筛选人工用例

原版退出后读取 [人工测试覆盖与筛选规则](references/manual-coverage.md)，逐个对照需求基线**角色×核心业务场景**与本轮实际执行的TDD、API/浏览器测试及代码评审证据：

- 真实已自动验证的行为：说明证据，不为凑表重复生成相同测试。
- 需要人判断的行为：视觉与原型一致、操作体验、复杂多角色审批/确认、真实第三方/设备交互、客户交付结果等，逐一形成可执行人工用例。
- 环境未到位/第三方未可用：标明“受阻”，不能写“真实集成已通过”或默默跳过。
- 确实无人工用例：生成简洁覆盖结论及所据证据，不强制造假用例。

按 [同表模板](assets/manual-test-template.md) 输出一份文档。用例必须明确ID、角色/场景、前置数据、人工操作、可观察预期，**实际结果、测试人、执行日期和证据均留空，状态一律待执行**。人工将在下一独立工作步骤填写**同一份**文档，不调用新的Skill。

## 4. 输出与退出关卡

- `code/` 本轮已有代码变更和版本化数据库迁移（存在时）。
- `docs/output/06-模块迭代/<模块>/实现与自动验证记录.md`：可定位的原版实现、测试和阻塞证据。
- `docs/output/06-模块迭代/<模块>/代码审查记录.md`：引用原版实际 `code-review` 结果，不另行审查。
- **`docs/output/06-模块迭代/<模块>/人工测试用例与结果.md`：本步骤只生成待执行用例。**

必须完成已就绪Ticket的原版实现与最终Review、明确自动覆盖范围和人工待执行项，才交给下一步人工操作。人工测试未完成不等于模块已验收，模块收口在后续执行。
