# 项目工程基线

> 正式文档只保留**已确认的项目级约束**。此文件是Skill内部模板，不是填写空壳。按项目删除不适用行/章节，并在输出中连续编号。每条约束至少可量化或可二值判定；缺关键数值时不得定稿。

## 1. 工程原则与取舍

| 适用条件 | 必须保证/优先级 | 明确禁止或可判定底线 |
|---|---|---|
| 仅保留已确认的项目级冲突取舍 | 例如：数据正确性优先于展示实时感 | 缺失数据不得伪装成真实采样 |

## 2. 工程禁止、现有资产与责任边界

| 适用对象 | 必须沿用/不可更改/责任归属 | 禁止边界与检验方法 |
|---|---|---|
| 当前项目前端原型（仅有时） | 经确认的页面风格与公共组件复用 | 不允许新建平行视觉和组件体系 |
| 已有后端框架或第三方（仅有时） | 保留已裁定的身份、数据或协议边界 | 不能把第三方无保证的能力当作系统承诺 |

> 不重述PRD中的「本期不开发某功能」。仅写工程禁止事项、不可变责任和系统对接边界。

## 3. 技术、兼容与运行环境约束

### 3.1 技术与工程兼容

| 领域 | 已批准的技术/版本或资产 | 允许变更/禁止变更条件 |
|---|---|---|
| 前端框架、构建器、组件库（适用时） | 真实版本/代码来源 | 哪类升级须审批 |
| 后端语言、框架与存储（适用时） | 真实版本/代码来源 | 兼容范围及既有资产保护 |
| 必要第三方、设备协议或特殊合规（适用时） | 已批准标准或协议 | 禁止替换/附加服务边界 |

### 3.2 部署和网络上限

| 资源或条件 | 已确认上限/范围 | 验证口径 |
|---|---|---|
| CPU/内存/磁盘 | vCPU/核、GiB、GB与盘类型 | 是现有硬件还是批准的采购目标 |
| OS与架构 | 版本、x86_64/ARM等 | 目标环境兼容 |
| 网络、出网及部署模式 | 内网/公网、端口、带宽、单机/多机限制 | 不得依赖未批准的网络或额外节点 |
| 可用资源余量 | OS预留、容器与备份开销、安全剩余容量 | 所有运行组件总预算不得超出边界 |

> **项目基线规定整机边界，不提前决定组件数或各服务配额。** 逐容器CPU/RAM/磁盘预算应由整体架构在此硬上限内闭合。

## 4. 目标业务规模与容量

| 对象 | 明确数值/单位/增长或时间范围 | 超限行为和验证口径 |
|---|---|---|
| 人员使用规模 | 总账号数、峰值活跃人数、请求速率/并发目标分别确认 | 在线人数不等于同时HTTP请求数 |
| 业务数据与附件 | 初始量、周期增长、保留年限、容量边界 | 未掌握单条大小不得伪称准确存储量 |
| 按需任务规模 | 单次数据量、同时发起量、执行时限、最长等待（含排队） | 超限必须明确拒绝/降级/排队边界 |
| 按需设备与测点规模 | 设备数、测点数、采样频次、峰值写入 | 仅IoT适用 |

## 5. 数据、安全与生命周期

| 数据对象或访问路径 | 必须/禁止的项目级约束 | 数值/口径/验证边界 |
|---|---|---|
| 权威来源、数据修订 | 只能使用允许的数据来源；确认结果不被静默覆盖 | 数据有效期、修订依据和可追溯检验 |
| 核心业务记录/附件 | 保留期限、起算点和归档/删除边界 | N年/月，跨引用的保留关系 |
| 普通运行日志/业务审计 | 分类留存和权限边界 | N天/月及最大占用量 |
| 身份、角色和数据隔离 | 后端权限和最小授权、外部访问边界 | 越权请求必须拒绝并可审计 |
| 敏感信息与第三方 | 数据出域、凭据管理、只读/写入限制 | 禁止的外部调用或操作可测试 |

## 6. 性能、稳定性与恢复约束

### 6.1 性能与测试口径

| 场景类别 | 经确认目标（数值、单位、统计方式） | 目标环境、数据量、负载、持续时长、计时边界 |
|---|---|---|
| 典型查询/保存/受理（只列实际关键场景） | P95/P99或可验证业务上限 | 明确服务端/端到端；用户量与并发分开 |
| 按需长任务 | 执行时长与端到端等待时长分别定义 | 同时执行、排队及超时状态 |
| 稳定性/容量保护 | CPU/RAM/磁盘预警或上限、持续运行条件 | 超限处理、内存/连接/日志不得无界增长 |

### 6.2 恢复边界

| 恢复对象 | RPO最大数据损失 | RTO最长恢复时间 | 可验证前置条件 |
|---|---|---|---|
| 数据库、附件、配置/必要依赖（按实际） | 已批准值及单位 | 已批准值及单位 | 已落实的备份介质、网络与恢复演练边界 |

## 7. 运维交付与基线变更

| 事项 | 必须实现的项目级结果 | 禁止/复评条件 |
|---|---|---|
| 观测与告警 | 能识别关键故障、资源上限、备份失败 | 不承诺不存在的监控平台 |
| 上线、恢复、移交 | 可在目标环境部署、恢复、诊断、回退 | 不使用未经批准的外部依赖 |
| 变更审核 | 技术版本、资源规模、数据年限、权限/数据来源改变须重新评估 | 不能为实现便利静默放宽正式约束 |

## 8. 条件专项及项目特有约束（实际触发才保留）

| 触发场景 | 经裁定的强制结果或禁止边界 | 数值/二值验收方法 |
|---|---|---|
| IoT / 计量 / 对接 / 异步 / 定时 / 审批 / Agent / 控制 / 多租户 / 信创的实际适用项 | 不写功能流程，写全局不可突破的工程条件 | 可量化的N、T、精度、容量；或明确是否违反 |
| 本项目特殊约束 | 从真实输入识别，不受固定类别限制 | 必须有真实证据及裁定 |

> 非适用专项不留空行；条款不得借演示值假称真实已确认。适用专项规则若已包含在其他章节可归并呈现，不制造重复规定。
