# 项目基线

> 类型：自建  
> 参考：obra/superpowers / skills/writing-plans/SKILL.md  
> 来源：[GitHub 源文件](https://github.com/obra/superpowers/blob/main/skills/writing-plans/SKILL.md)  
> 本文是针对项目场景的原创实现说明，并非上游 Skill 原文。

## 一、职责与边界

本 Skill 只负责「项目基线」，从确定的输入形成可审核输出，不越权替代其他步骤。  
项目原型基线是 `code/fld/`；后端框架是 `code/guiwu_ruoyi/`。PRD 位于 `docs/input/需求资料/`，其他可选输入位于 `docs/input/工程资料/`、`docs/input/环境资料/`、`docs/input/对接资料/`。不重做已确认PRD，不独立设计另一套前端视觉与交互体系。Git提交说明使用中文。

## 二、触发条件

当前研发工作流执行到「项目基线」，且存在所需输入或已记录的阻塞项时调用。无权访问或无法验证时明确给出阻塞状态，不虚构结果。

## 三、输入

- `docs/input/需求资料/PRD`
- `docs/input/工程资料/已定方案与技术栈`
- `docs/input/环境资料/`
- `docs/input/对接资料/`
- `docs/output/01-项目基线/输入核对.md`

## 四、执行流程


### 执行准则

1. **读取已确认PRD**：读取对应上下文和实际证据，检查与前序项目基线的关系，记录决定和异常。
2. **提取项目共性约束**：读取对应上下文和实际证据，检查与前序项目基线的关系，记录决定和异常。
3. **核对工程资料**：读取对应上下文和实际证据，检查与前序项目基线的关系，记录决定和异常。
4. **评审基线**：读取对应上下文和实际证据，检查与前序项目基线的关系，记录决定和异常。







## 五、输出

- `docs/output/01-项目基线/项目基线.md`

## 六、验收与中止条件

项目经理确认业务交付边界；开发人员确认已选技术栈、原型复用和部署约束有据可依。

若输入文档不支持技术结论、第三方接口未确认、实测环境不可达，应输出待确认项并中止受阻部分。产出必须与本项目的PRD、源码和工程基线一致。
