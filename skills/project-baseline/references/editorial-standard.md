# 工程基线正文写作规范

## 文档定位

只定义项目级约束：**不重写PRD、不提前做设计**。每条应能判断某方案/实现是否合格。数值类采用指标、数值和单位、统计/起算口径、适用条件与测量范围；禁止类用明确的必须/不得及可验证判据。允许使用文字规则，不强行制造毫无意义的精确数字。

## 编写规则

- 按「取舍 → 工程禁止/职责 → 技术与运行环境 → 规模容量 → 数据安全 → 性能恢复 → 运维变更 → 条件专项」组织；连续编号（## 1.、### 1.1），不设置冗长条款编码。
- 同类信息用2—4列紧凑表格，一行一项，避免大段话。
- 模板仅是检查提纲。未适用行/章节删除，编号顺延；禁止堆「不适用」。
- 正文只保留已裁定约束，不写扫描日志、推荐池、调查问答、测试报告、工作流程或未确认占位。
- 明确「事实硬件/目标硬件」、「业务规模/工程并发」、「目标值/实测值」、「整机资源上限/架构分配预算」区别。
- 项目特殊约束不能为了沿用模板而丢失；可以归入相关章节或增加按需小节。
- 不输出没有约束效力的「核心约束摘要」或PRD功能清单。

## 反例与正例

❌ 「系统需要提供文件导出功能」——需求，不是基线。
❌ 「导出使用RabbitMQ和两台Worker」——未批准时属于设计。
❌ 「系统应具备高性能、稳定可靠」——无可验口径。
✅ 「在已确认峰值负载和数据集下，关键接口服务端P95不超过已裁定的N秒；N未确认时暂不定稿」。
✅ 「客户第三方数据源仅授权查询，不得写入/修改其结构；通过对接账号权限和操作审计判定」。
✅ 「在现有原型基础上开发，不另建一套视觉风格/公共组件；允许已批准的局部调整」。
