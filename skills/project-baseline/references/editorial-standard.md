# 工程基线正文写作标准

## 读者顺序

第一性原则及取舍 → 业务与技术工程边界 → 运行规模与资源 → 可判断质量指标 → 恢复与交付。

- 正文仅保留定稿约束，不写元信息、材料索引、来源编号或分析过程。
- 章节连续编号：`## 1.`、`### 1.1`，不使用专有条款编码。
- 同类信息使用2-4列紧凑表格，一行只表达一项约束。长单元格继续拆分。
- 数据增长必须有对象、计算口径与数量级；内存/磁盘预算注明测量边界。
- 数据一致性按“场景—必须保证结果”分行。
- 区分指标目标与测试口径：环境、负载、数据量、统计量（P95等）、持续时间分别写清。
- 不输出“核心约束摘要”、待填写空表或未确认事项列表。
- 不靠罗列“不适用项”凑篇幅，无关章节删除且后续编号顺延。

## 反例

❌ “系统应该高性能、安全、无内存泄漏。”

✅ “在**已确认的目标环境和负载条件**下，95%的关键查询服务端响应时间不超过已约定阈值；连接和队列有上限，超过上限时拒绝或降级并记录告警。”

❌ “预计50人在线，所以数据库需承载50并发请求。”

✅ “50个在线用户与请求瞬时并发为两种口径；后者未确认时只提出建议，不擅自定值。”
