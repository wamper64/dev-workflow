# 必须量化的约束与数值闭合规则（Skill内部）

本文件用于判断生成的基线是否真能约束设计。一个章节被创建不代表其中已有合格约束。

| 类别 | 必须定出的实际量或目标 | 禁止替代的模糊话术 |
|---|---|---|
| 技术栈 | 前端框架/构建/UI库版本、Java/Spring Boot/RuoYi版本、DB/缓存/消息按需版本 | 沿用现有技术 |
| 服务器 | CPU架构/vCPU、总内存/可用内存GiB、总磁盘/可用磁盘GB与类型、OS版本 | 中小型服务器 |
| CPU预算 | OS/代理、数据库、API、worker/后台任务、其他服务分项core/vCPU | 合理分配CPU |
| 内存预算 | OS、MySQL、API、worker、Redis/网关、安全余量的绝对GiB上限 | 内存不泄漏 |
| 磁盘预算 | 系统镜像、数据库索引、附件、日志、临时、本地备份、空闲空间各分项GB | 留足磁盘空间 |
| 并发 | 在线人数、同时HTTP请求、长任务同时执行数、排队上限与超载行为 | 支持50并发 |
| 数据保留 | 报价/人工确认版本/计算单/业务审计/附件/运行日志的N年或N月和起算点 | 长期保存 |
| 性能 | 场景P95/P99阈值、错误率、目标数据规模、并发、测量边界和时长 | 页面响应快 |
| 稳定性 | 常驻RSS、连接数、线程数、句柄数、磁盘日志上限、浸泡时长与恢复水位 | 系统稳定 |
| 恢复 | RPO/RTO、备份间隔、备份对象、离机或本机真实位置与恢复验证 | 定期备份 |

预算闭合强制：
- CPU各分项合计≤目标核数（没有批准的超分配不能算合格）。
- 内存OS+各进程/容器+缓存/数据库+安全余量≤机器内存。
- 磁盘系统+库+附件+日志+临时+本机备份+空余≤磁盘总可用容量。
- 保存年限×年增长量和现有存量≤数据库/附件预算；不能因为保留5年就声称GB足够。
- 本地备份区无法容纳所有对象时，须独立确认其他备份目的地；不能假称外部存储存在。
- 50人在线≠50 HTTP请求并发≠50长任务并行。
- 性能目标不等于实测已达标。
- 数值必须来自当前项目事实/已确认目标/用户授权裁定；未确认的候选值只能留在询问和演示中。

**内部演示预算：** 8 vCPU=OS/代理1+数据库2+API2+长任务2+缓存1；16GiB=OS3+MySQL4+API3+worker2+缓存1+网关0.5+余量2.5；500GB=OS镜像60+DB110+文件150+日志20+临时30+本机备份中转50+空余80。以上只是数值闭合例子，不能自动视为报价项目已确认值。
