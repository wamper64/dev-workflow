# 可量化、可验证的工程约束标准

## 0. 三个主词

- **台账**：需要穷尽枚举的清单——技术栈台账、数据类台账、基础设施台账；判据是「无遗漏」（行数 = 材料中实际存在的项数）。
- **落定**：值已由负责人裁定并可写入正式基线；否则为**未落定**，只留在对话，不入正文。
- **闭合**：把一类量算到可与上限比较的总量（如「每类数据小计 → 合计 → 与磁盘比大小」），并给出具体余量数值。

## 1. 从需求中提取量化信息

每项能量化的需求事实，按「对象—指标—数值/阈值—单位—统计窗口/起算点—适用条件—证据」记录，不能只摘一句「支持大量数据」。

| 信息类别 | 提取条件与单位 | 不得混淆 |
|---|---|---|
| 使用规模 | 注册/在线/峰值活跃人数、人均操作次数/分钟、高峰持续分钟 | 在线人数≠瞬时HTTP并发 |
| 设备/IoT（适用时） | 设备台数、测点数/台、采样周期秒、峰值报文条/秒、延迟上限秒 | 采样周期≠传输到达时效 |
| 业务数据 | 初始条数/GB、增长条/天或GB/年、保留年/月、起算日 | 数据条数不能直接等于GB |
| 附件与任务（适用时） | 单次MB/条数、同时发起量、最大执行分钟、最长等待分钟 | 执行耗时≠排队+执行总等待 |
| 准确性/时效 | 精度/小数位、舍入方式、T+1或最大延迟、准确率统计样本 | 原始数据缺失≠有效零值 |
| 目标资源 | 生产vCPU、可用RAM GiB、磁盘GB及类型、预留余量 | 整机上限≠已分配各容器配额 |
| 性能与恢复 | P95/P99秒、错误率%、可用率%、RPO/RTO小时 | 测试目标≠已测事实 |

## 2. 用户只给业务事实，AI 提出可审查工程候选

- 用户可提供「高峰有N人操作、每人每分钟M次、每次约K个API请求」。**平均请求速率候选RPS = N×M×K/60**，另根据集中峰值/自动轮询提出峰值系数及实际压测目标。
- **同时在处理的请求数≈RPS×平均响应时间（秒）**，仅作容量估算：应考虑慢接口、峰值波动、长尾和后台负载；HTTP并发必须由技术负责人裁定，不可仅由在线用户数机械换算。
- IoT按「设备数×测点数/设备×每测点采样率」估算数据点/秒，考虑批量报文、补传峰值与存储格式。
- 对无法从需求推导的性能SLA、RPO/RTO、设备硬件事实给出带条件的选项供授权人裁定，不能AI自主宣告承诺。
- **所有推导仅是候选；未落定前不得写进正式基线正文。**

## 3. 数据类台账与容量闭合（必做）

不得只算「记得住的那一类数据」。步骤：

1. **建数据类台账**：逐一列出互不重叠的持久化存储科目——时序、日志/审计、回执、附件、MQ 落盘、备份等——每类一行，每行有唯一科目ID、承载介质、是否包含索引/副本与是否已计入其它费用。
2. **逐类估算**：`基础量 = 单条尺寸 × 增长率 × 保留期`；索引、压缩、复制等系数必须说明是“本行包含”还是“单独一行”，不可重复。缺单条尺寸或压缩比时给区间与依据并标注估算，**不得跳过该类**。
3. **合计与闭合**：互斥科目合计 + 未计入的系统/临时开销 + 独立安全余量 = 总量（每项只计一次；日志、备份、附件若已有单独行，不得再次相加）；与磁盘上限比大小，给出**具体余量数值**。
4. 时序类可按 `设备数 × 测点数 × 采样率 → 条/秒 → 条/年` 展开，但必须把所有数据类都纳入，而非只列其中一类。

## 4. 基础设施量化（有则必做）

凡台账中出现的基础设施组件，须给自身量化约束：消息队列（峰值吞吐、积压上限、TTL/保留、重试次数、死信上限与处理、持久化）、缓存（容量、淘汰、过期、持久化）、调度（实例、并发、错过触发处理）、对象存储（容量、生命周期、版本/副本）、网关/代理（并发连接、超时、限流）。

## 5. 资源余量量化

整机上限之外，必须给出**量化余量**：OS 预留、中间件与代理开销、备份与快照占用、安全剩余——各项为具体数值（或明确比例+基数），使「各运行单元预算 + 预留 ≤ 上限」可核算。逐服务配额仍属整体架构。

## 6. 不强迫非数字规则伪量化

「不得重建原型视觉体系」「第三方只读」「AI不得越权」「模拟不能冒充真实成功」采用**二值验证**。规则应明确适用边界、违反条件和复核方式，而不是编造数值去满足形式要求。

## 7. 数值与证据状态

已知硬事实、已批准目标、计算出的候选、AI推荐、未知五种状态不混写。**已落定**才可进正式基线；候选与推荐必须给单位、适用前提、成本/降级取舍，且只留对话。目标应能通过后续测试/审计证明，而不声称生成文档时已实测。

**去重验算**：对每个存储内容建立唯一科目映射；同一份附件/日志/备份不可同时属于基础数据行和附加费用。例：100GB业务 + 40GB附件 + 20GB日志 + 100GB备份 = 260GB（不含尚未计入的索引及余量）；若再加附件40GB为错误。
