# 项目基线生成与放行检查

基线**不是需求、不是设计，是项目级工程约束**。审核不仅检查有无章节，更检查条款是否能否决不合格方案。

## 六项放行关卡（缺关键项不得定稿）

- [ ] **覆盖完整**：8项通用维度已检查；IoT、关键计算/计量、第三方、后台异步、定时、审批、Agent、远程控制、多租户、信创等专项按实际输入触发；项目特有的工程禁止项和责任边界没有遗漏。
- [ ] **约束明确**：每条具有适用条件、必须/禁止、工程边界；没有把PRD中的功能清单或本期不做功能抄成基线。
- [ ] **可量化或可判定**：从需求能提取的数值已包含值、单位、时间/统计口径和来源；非数值禁止项有可测试的通过/不通过标准；推导值标注假设。
- [ ] **前后一致**：资源目标/余量、业务负载、数据增长×保存期、性能环境、数据权限/权威、RPO/RTO和真实备份能力相容。
- [ ] **不越设计边界**：不规定未经批准的组件拓扑、表结构、API、Worker数量、线程池、缓存策略或逐容器资源分配；团队TDD/Tickets/代码审查不属于项目基线。
- [ ] **关键项已裁定**：前置表已自动预填已知信息；只问真实缺口，已确认不会重复问。关键待决不得被示例或AI推荐代替；项目经理/技术负责人按职责审核。

## 数值抽取和容量检查

| 检查方向 | 达标含义 | 常见错误 |
|---|---|---|
| 技术栈 | 实际已批准的框架、产品、版本及兼容边界 | 「沿用现有技术」，却不核实锁文件 |
| 生产环境 | CPU架构/vCPU、RAM GiB、磁盘GB及类型、OS、网络与扩容边界 | 客户没给硬件却照搬报价示例 |
| 规模负载 | 总用户/在线/活跃、请求速率/并发、按需异步并行、排队及超载口径分离 | 50人在线=50HTTP并发 |
| 容量与数据 | 初始量、年增长、保留期、附件/索引/日志/备份及安全余量可解释 | 只说「长期保留」 |
| 性能 | 关键场景P95/错误率等有数值/单位、数据集、负载、测量边界和测试时长 | 只写「高性能」 |
| 恢复 | RPO/RTO、实际备份条件和恢复范围相互匹配 | 本机备份被写为已具备离机恢复 |
| 特有禁止 | 复用原型、数据只读、故障真实状态等有条件和验证方式 | 把PRD本期不做事项列成禁止项 |

## 失败与回退

不满足时产出「项目基线前置约束确认表」并说明阻塞。对缺少的数值给出候选区间/具体推荐、依据、风险和待裁决人（每轮最多3组高影响问题）；不能提交完整已确认的项目基线。
