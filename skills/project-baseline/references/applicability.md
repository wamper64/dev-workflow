# 通用核心维度与专项适用性判断

## 不增加项目功能需求

系统形态仅帮助定位约束：通用Web、IoT+Web、Agent+Web及混合形态；可以叠加。不要根据形态推定真实项目已具备该技术，不向用户再做一轮功能需求收集。

## 所有项目检查的八个约束维度

| 维度 | 必须确认的约束对象 | 不进入基线的设计事项 |
|---|---|---|
| 1 工程原则与取舍 | 冲突时正确性/安全/成本/时效等已裁定优先级 | 采用什么算法权衡 |
| 2 工程禁止及责任边界 | 禁止行为、既有责任归属、已有资产不能改范围 | PRD功能清单和分期功能规划 |
| 3 技术与工程兼容 | 已批准框架/版本/升级边界、既有工程复用 | 代码分层和运行组件划分 |
| 4 运行部署与网络 | OS/硬件/出网/部署资源上限、扩容限制 | 容器拓扑和逐服务配额 |
| 5 规模、负载与容量 | 在线/活跃/请求、数据增长、任务和附件规模 | Worker数量、线程池大小、队列产品 |
| 6 数据、安全与生命周期 | 权威源、保留期、权限隔离、敏感数据边界 | 表、字段、具体索引 |
| 7 性能、稳定与恢复 | P95/错误率、峰值、RPO/RTO、持续运行 | 缓存策略、备份软件实现 |
| 8 运维交付与基线变更 | 必须具备的监测/恢复/交付能力、变更审批阈值 | 具体脚本和工具选择 |

## 条件专项（可叠加，可不适用）

| 触发证据：仅从既有输入识别 | 约束抽取重点 |
|---|---|
| 物联网/设备接入：设备、MQTT、Modbus、网关、采样 | 设备身份、时效、断线补传、乱序/重复、异常值和故障隔离 |
| 关键计算与计量：金额、能源、电表、库存等关键结果 | 单位、精度/舍入、统计周期、缺数、重算和历史修订 |
| 第三方对接：API、只读库、ERP/MOM/MES | 权威来源、读写许可、故障降级、同步时效、重复处理 |
| 后台异步任务：批量导入导出、分析、长计算 | 单次规模、总等待/执行时限、重复和取消、资源/队列上限 |
| 定时任务：按日/月/周期自动运行 | 调度时间、补跑窗口、重入、失败告警、数据时区 |
| 审批/工作流：角色多级确认、驳回或撤回 | 权限、版本追溯、一次完成语义、驳回一致性 |
| Agent/智能操作：AI输出、MCP、工具、知识检索 | 数据出域、权限继承、人工确认、状态真实性、审计 |
| 远程控制/高风险操作：设备指令或重大业务变更 | 授权、控制禁令、确认、超时、反馈结果和安全联锁责任 |
| 多组织/多租户：共享系统隔离不同客户/组织 | 数据/账号隔离、跨域访问、共享资源边界 |
| 信创或特殊合规：合同限制国产化或安全等级 | 目标兼容环境、供应链、数据边界及证据要求 |

注意：
1. 「能源/计量」不再是与系统形态并列的强制项目类别；按是否存在关键计算/计量风险决定。
2. 「长任务」「定时任务」「业务审批」三者必须分开识别，不能从其中任一项推断另两项。
3. 「第三方对接」从合同或接口材料发现即可触发，不依赖用户手工勾选。
4. 仅与单一页面相关的普通细节不提升为全局基线。
5. 在上述目录之外仍必须识别并加入**项目特有约束**；非固定类别不可遗漏。
