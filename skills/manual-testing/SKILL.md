# 独立人工测试与验收闭环

## 输入

- 当前独立Spec/Tickets（S09建立的稳定 `module_key → 任务ID → Tracker URL/feature-slug目录` 映射所指向的真实Spec/Tickets（不假定某种本地目录））、本轮已确认PRD/原型中角色×核心业务场景及模块最新有效设计。
- Matt**原版implement-spec**的真实TDD执行命令与输出、API/浏览器测试证据、Git提交与最终Standards/Spec代码审查结果；不存在不能谎称已通过。
- 真实测试账号、前后端环境、设备或第三方可用性（密钥不写文档）。
- `docs/output/项目总控/项目实施状态.md`、模块依赖图和历史任务验收记录。

## 执行步骤

1. 每个本轮角色×核心场景对照原版自动化执行证据，标明 **已自动覆盖 / 本可自动却漏测 / 必须人工验证 / 现实条件受阻**，参考[判定规则](references/manual-coverage.md)。已自动验证的只引用证据，不重测；应自动补测的交回实现阶段（Matt 原版 implement-spec），不转给人工凑数。
2. 真实人工判断或操作才生成测试用例，例如既有原型视觉与体验、真实多角色授权流程、真实第三方/设备现场、客户可见交付结果。无条件时标受阻，Mock不能作为真实业务验收。
3. 输出到映射确认的任务证据目录（本地默认 `.scratch/<feature-slug>/人工测试用例与结果.md`；远程 Tracker 则引用对应 Issue/证据目录），文件位置回填任务映射，按[同表模板](assets/manual-test-template.md)写用例ID、角色×场景、前置数据与权限、逐步操作、可观察通过标准。**实际结果、执行人、执行日期、证据保持空白，状态一律待执行**。无人工用例则只写有真实证据的自动覆盖结论，不虚构用例。
4. 开发/测试人员在实际环境操作并在**原文件**回填真实结果、执行人、日期、证据；失败需登记缺陷，按需用Matt**原版**`diagnosing-bugs`诊断，修复后人工按**原用例ID**新增一次独立执行轮次复测，不覆盖首次失败事实；每轮绑定镜像digest/构建Commit、迁移/配置摘要、环境版本、数据快照、执行人/时间及真实证据。
5. 本轮关键场景真实通过，开发人员完成技术签收、项目经理完成业务签收后，按[签收记录模板](assets/signoff-template.md)生成当前任务映射的证据目录下的 `模块验收与状态记录.md`，再**增量更新**`docs/output/项目总控/项目实施状态.md`，保留所有历史任务。一个任务签收≠模块全部签收；未测/失败/受阻不得标完成。

## 退出条件

- 人工测试由人实际执行，AI仅生成待测用例与证据汇总，不代填实际通过与签收。
- 不额外执行Matt的TDD、implement-spec或code-review；不替Matt retro做AI会话复盘。
- 已真实签收的任务可进入Matt原版retro；存在未完成模块则下一轮返回module-design，全部模块签收才能进入全项目业务验收。

**签收绑定（F16）**：用例定义与执行结果分离。每一次运行（包括失败与再次复测）新增不可覆盖记录 `执行轮次ID｜用例ID｜测试构建Commit/镜像digest｜环境/迁移/配置版本｜测试数据版本｜人/时｜真实结果｜证据`。签收仅对明示的构建与条件有效，修Bug重新构建后受影响用例必须复测，不得将 A 版本的通过移作 B 版本的证据。
