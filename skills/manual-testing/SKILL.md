# 独立人工测试与验收闭环

## 输入

- 当前独立Spec/Tickets（`.scratch/<模块>/<任务标识>/`或配置的Issue Tracker）、本轮已确认PRD/原型中角色×核心业务场景及模块最新有效设计。
- Matt**原版implement-spec**的真实TDD执行命令与输出、API/浏览器测试证据、Git提交与最终Standards/Spec代码审查结果；不存在不能谎称已通过。
- 真实测试账号、前后端环境、设备或第三方可用性（密钥不写文档）。
- `docs/output/项目总控/项目实施状态.md`、模块依赖图和历史任务验收记录。

## 执行步骤

1. 每个本轮角色×核心场景对照原版自动化执行证据，标明 **已自动覆盖 / 本可自动却漏测 / 必须人工验证 / 现实条件受阻**，参考[判定规则](references/manual-coverage.md)。已自动验证的只引用证据，不重测；应自动补测的交回S12，不转给人工凑数。
2. 真实人工判断或操作才生成测试用例，例如既有原型视觉与体验、真实多角色授权流程、真实第三方/设备现场、客户可见交付结果。无条件时标受阻，Mock不能作为真实业务验收。
3. 输出`docs/output/06-模块迭代/<模块>/任务/<任务标识>/人工测试用例与结果.md`，按[同表模板](assets/manual-test-template.md)写用例ID、角色×场景、前置数据与权限、逐步操作、可观察通过标准。**实际结果、执行人、执行日期、证据保持空白，状态一律待执行**。无人工用例则只写有真实证据的自动覆盖结论，不虚构用例。
4. 开发/测试人员在实际环境操作并在**原文件**回填真实结果、执行人、日期、证据；失败需登记缺陷，按需用Matt**原版**`diagnosing-bugs`诊断，修复后人工按**原用例ID**复测，不覆盖首次失败事实。
5. 本轮关键场景真实通过，开发人员完成技术签收、项目经理完成业务签收后，按[签收记录模板](assets/signoff-template.md)生成`任务/<任务标识>/模块验收与状态记录.md`，再**增量更新**`docs/output/项目总控/项目实施状态.md`，保留所有历史任务。一个任务签收≠模块全部签收；未测/失败/受阻不得标完成。

## 退出条件

- 人工测试由人实际执行，AI仅生成待测用例与证据汇总，不代填实际通过与签收。
- 不额外执行Matt的TDD、implement-spec或code-review；不替Matt retro做AI会话复盘。
- 已真实签收的任务可进入Matt原版retro；存在未完成模块则下一轮返回module-design，全部模块签收才能进入全项目业务验收。
