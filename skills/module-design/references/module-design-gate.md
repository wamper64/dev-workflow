# 本轮模块选择、依赖校验与详细设计关卡

- [ ] 读取模块池与状态，按真实审核模块清单首次初始化项目状态；后续不重置。
- [ ] 本轮独立任务范围、角色×场景、非目标和责任人明确；已完成历史Spec/Tickets不能覆盖。
- [ ] 已核对上游模块、共享数据/权限、设备第三方/测试环境并分类就绪/可并行/阻塞。
- [ ] 真实阻塞或S04/S05核心契约冲突时暂停受影响任务，不进入Spec。
- [ ] 项目经理确认本轮范围，开发人员确认前置环境与可验收目标。

| 项目 | 可客观审核的事项 |
|---|---|
| 全局架构继承 | 引用总体组件ID、组件关系双方+协议/场景和A/B/C冻结条目，核对实际前后端工程落点与已有能力复用；不得自行新增Worker、通信协议或更换状态Owner，必要变更退回技术总监 |\n| PRD匹配 | 每条角色×场景有页面入口/接口动作/成功与失败结果 |
| 原型继承 | 现有 code/ 下真实原型路由、主布局、组件和样式不被重复改造 |
| 复用若依 | 登录、角色、菜单、数据权限和审计按实际已有能力复用 |
| 状态机 | 业务成功、失败、驳回/重提、取消、重试能形成状态迁移 |
| S05核心数据继承 | 已引用全局核心表、核心字段/类型/唯一约束、ER关系、写入Owner及数据生命周期，不重建同义核心表；改变A级契约先回S05，影响架构则再回S04 |
| 字段与版本 | 模块仅细化必要的非核心字段、辅助表、索引及事务权限，完整字段/版本能支撑真实规则 |
| 迁移 | 迁移设计草案含执行顺序、老表兼容、备份/回退边界，正式SQL在编码阶段形成并同步回写设计 |
| API | 动作、路径、请求/响应、错误码、权限、分页和幂等均明确 |
| 依赖 | 生产者/消费者契约、版本差异和第三方真实可用性界定 |
| 量化基线 | 并发、数据保存、运行资源与关键P95等已在设计里有可执行控制点 |
| 测试 | 有能观察真实业务结果的API/服务级或UI测试接缝 |
| 质量门禁 | 只负责当前迭代模块，不触及总体架构的隐式变更 |

以上不是统一的“每模块必须12张表”，应按实际适用规则做差异化设计，不适用需说明原因。
