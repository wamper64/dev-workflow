# iteration-close 审核门禁

1. [ ] 读取本轮Spec/Tickets、code-review、实际自动联调报告与人工测试签收记录，逐个核实相互引用的版本。
2. [ ] 核验阻塞Bug是否有复现→诊断→修复→审查→联调→人工复测的完整链路；第三方受限项有明确项目经理批准状态或不能关闭。
3. [ ] 只将已签收的模块写“已验收”，其余维持开发中/受阻/未开始，并同步剩余模块依赖图。
4. [ ] 对重复的Agent编码/协作问题按需调用Matt retro，形成一条实际可执行的环境或CI改进提案；不每次强制复盘。
5. [ ] 若仍有模块待开发，返回选择本轮模块；全部满足项目PRD覆盖后，才申请进入全系统验收。

## 退出标准

人工签收真实、关键Bug关闭、业务依赖状态一致；否则继续修复与复验。

所有确认须说明实际证据及未完成阻塞，不得以用户尚未回答的推荐代替事实。
