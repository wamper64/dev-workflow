# 本轮模块验收收口

## 输入

1. 需求基线：`docs/input/需求资料/` 中已确认的角色×核心场景。
2. `docs/output/06-模块迭代/本轮模块计划.md`、本轮Spec/Tickets/模块详细设计。
3. **implement-spec** 实际执行与内置代码审查证据：TDD和必要前后端集成验证、代码审查的Standards与Spec结论、提交版本。
4. **人工结果**：`docs/output/06-模块迭代/<模块>/人工测试用例与结果.md`（由人工填写，不是AI预估）。
5. 有Bug时，Matt `diagnosing-bugs` Phase1~6根因和修复证据、同一用例的人工复测。
6. 项目模块清单及依赖关系、当前 `docs/output/项目总控/项目实施状态.md`。

## 工作逻辑

1. **读取真实证据**：检查本轮每个模块对应Git提交、Spec/Tickets、TDD/集成验证与implement-spec内置的code-review，不单独再启动代码审查或重做自动测试。
2. **检查人工结果**：每条关键角色×场景至少有真实执行人、实际结果和证据；仍待执行/失败/受阻的不算通过。
3. **核查Bug闭环**：需要重现、定位、修复后原始症状消失、回归测试与**人工对原用例复测**，未关闭阻塞缺陷不收口。
4. **人工签收**：开发人员确认技术证据，项目经理确认业务结果及剩余风险，只有批准模块才标已验收。
5. **解锁下一轮**：更新唯一项目状态文件、依赖关系和剩余范围；有剩余模块返回本轮选择，全部通过再进入系统验收。必要时调用Matt retro审查反复出现的Agent协作问题，但它不等于业务验收。

## 输出

- `docs/output/项目总控/项目实施状态.md`
- `docs/output/06-模块迭代/本轮收口记录.md`

## 证据关卡

| 条件 | 不满足时 |
|---|---|
| implement-spec实际TDD/必要集成验证 + 内置review有证据 | 返回实现继续完成 |
| 角色场景人工测试在原同一md真实回填 | 继续人工操作，不由AI代填 |
| 高风险Bug已按官方六阶段诊断修复且人工复测通过 | 回到Bug处理，不得签收 |
| 项目经理签收当前模块 | 保持开发中或受阻 |
| 所有模块已验收 | 进入下一轮，不得跳转总验收 |
