# 项目研发导航（报价系统）
基于已有 `input/` 资料、`code/fld` 前端原型和 `code/guiwu_ruoyi` 若依框架，设计首次项目建设研发流程。

## 第一阶段：只审核报价系统
当前提供 5 个阶段（含第0阶段）、23 项导航内容、13 个待审核模块，以及 8 步模块迭代循环。模块与Spec数量都不是强制预设。标准项目模式将在报价流程获得确认后再建设。

## 在线地址
https://wamper64.github.io/dev-workflow/

需要在 GitHub → Settings → Pages 中选择 **GitHub Actions** 作为 Source。站点使用 `docs/` 目录并由 `.github/workflows/deploy.yml` 自动发布。

## 后期修改
研发流程和模块唯一数据源为 `docs/data/quotation.json`，HTML、CSS、JS 仅作为展示层。修改JSON并提交 `main` 后自动重建并发布；所有 Git 提交说明使用中文。

## 当前保留的约束
- `input/需求资料` 保存确认的PRD；`input/工程资料`、`环境资料`、`对接资料` 按已有资料提供。
- 前端只在现有原型上开发，已有样式、组件和风格必须沿用；不得重搭另一套。
- 后端在已有若依工程上扩展。
- 先识别审核模块，再选择本轮已确定模块，按Spec/Tickets/TDD/评审/集成迭代。
- 下一阶段再加入完整Skill正文、示例、模板及导出。
- 公开网站只展示方案与脱敏信息，不存放真实客户文档及密钥。

## 当前流程阶段
项目基线 → 整体架构设计 → 数据库设计（总体，仅数据域、存储与分库分表策略） → 开发环境部署（数据库、缓存及必要中间件） → 模块拆分 → 模块迭代开发 → 全项目验收与生产部署 → 复盘与沉淀（Matt `retro`）。

页面三栏布局：左侧阶段、中间步骤（窄栏）、右侧详情（Skill/输入/输出/审核/中文执行提示词）。每步提示词可单独复制。修改 `docs/data/quotation.json` 后，GitHub Actions 自动生成内联CSS/JS/数据的单文件页面。

## 当前主流程（2026-10-10）
0 准备工作（既有 input/ 与 code/）→ 1 项目准备与设计（审核输入、初始化项目、项目基线、整体架构、数据库总体、开发环境、模块拆分）→ 2 模块迭代开发 → 3 全项目验收与部署上线 → 4 复盘与沉淀。

所有可执行步骤的提示词均明确列出需要调用的 Skill 名称与顺序；第0阶段仅展示原始输入，不运行Skill。
