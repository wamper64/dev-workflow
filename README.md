# 标准项目研发导航

**在线地址**：https://wamper64.github.io/dev-workflow/

本仓库面向定制前后端及Agent+前后端项目的首次建设流程。报价系统仅用于独立的Skill输出示例，不限定项目名称、现有代码子目录或技术栈。

## 固定输入与边界

```text
项目根目录/
├── docs/
│   ├── input/
│   │   ├── 需求资料/       # 已确认PRD，包含原型页面映射
│   │   ├── 工程资料/       # 前期架构、方案、技术选型（可选）
│   │   ├── 环境资料/       # 服务器/开发环境（可选）
│   │   └── 对接资料/       # 第三方或设备接口（可选）
│   └── output/            # 各阶段正式产物
├── code/                # 既有项目工程；子目录名称由真实项目决定
└── skills/              # 可安装Skill目录，不含任何项目输出示例
```

严禁在原型之外重搭一套风格；业务开发可改页面数据及小范围细节，不重做已有原型视觉与通用组件。已确认的PRD不在本阶段重新制定。

## 网站

左栏为工作阶段，中栏为步骤，右栏为所用Skill、输入、输出、审核和可复制中文提示词。点击Skill可以选择按其特点设计的快速理解、报价项目示例、完整目录文件以及**逐文件开源研究来源与实际借鉴机制**。

左侧「工作阶段」下方独立展示「通用 Skills」入口（共7项，含handoff、grilling、research、domain-modeling、wizard、pr和to-questionnaire）；右侧可查看用途、执行方式与官方全部文件。右上角新增「项目目录树」：按当前四阶段、每个步骤的预期产物绘制完整树并加中文注释，支持复制；另可下载全部Skills ZIP。

## 当前流程

| 阶段 | 工作内容 |
|---|---|
| 0 准备工作 | 展示已确认docs/input/资料与既有code/，不调用Skill |
| 1 项目准备与设计 | 输入确认→Matt初始化→项目基线→整体架构（内部Grill）→数据库总体→**S06按环境预填部署配置、确认后首次部署**→模块拆分 |
| 2 模块迭代开发 | **module-design选择/依赖/详细设计**→Matt to-spec→to-tickets→**原版implement-spec**→**独立manual-testing**生成用例/人工回填/签收→按需diagnosing-bugs→**原版retro**→下一轮 |
| 3 全项目验收与部署 | 系统业务验收→非功能上线评审→生产预演与回滚→正式部署交接 |

共**4个阶段、20个导航步骤**，其中准备工作2项只展示输入，S01无独立Skill。Skill目录含**19份主流程/内部调用Skill**，另有7个通用工具与3个官方依赖，共**29份SKILL.md**。实际模块数量须从PRD识别；报价项目的案例单独放在 `docs/examples/报价项目/`。

## Skill质量与采用原则

- **Matt官方原版**：在不更改内容的前提下复用，不重写成“二次封装”。
- **基于Matt改造或自建**：先研究真实开源SKILL.md，按定制前后端、已有代码/原型保真、角色审核和真实证据规则改造，不预设特定框架。
- **模块拆分（S07）**：采用Matt官方`to-tickets`的方法改造为**全项目模块级**的纵向业务交付、Blocked by依赖与Quiz审核；不提前把全项目模块发布为可执行开发Tickets。**S11继续使用未修改的Matt原版**`to-tickets`基于已审定本轮模块Spec生成真实开发Tickets。
- **项目基线（S03）**：先从PRD、原型、代码及环境/对接资料提取可量化的工程事实和可判定禁止项，自动预填前置约束确认表，只让用户裁定真实缺口；正式基线只写约束，不写需求或设计。整机资源上限由S03约束，逐组件资源预算留给S04。
- **其他自建/改造**：已补齐专项执行流程、可判断检查关卡、产物模板和报价业务示例，目前为**可评审初版**，仍需真实项目演练和人工确认，不以模板齐全代表已成熟。
- 来源及“参考了什么机制”：见 [逐Skill调研记录](docs/research/skill-sources.md)。研究资料独立于可安装Skill正文。

## 自动发布与保护

GitHub Pages源设置为 **GitHub Actions**。每次提交`main`后，`.github/workflows/deploy.yml`构建带内联资源的网站及Skills ZIP，并测试基本的阶段、步骤、Skill目录、Grill、人工测试和通用工具交互。CI失败不发布。

开发约定：所有Git提交消息使用中文；本公开仓库不存真实客户PRD、生产密码或未脱敏接口数据。

- S12只调用Matt原版实现与审查；S14H独立manual-testing生成待测单，实际人员在同一文件回填结果并签收。

## 2026-10-12：整体架构双核心

- 核心一“总体组件架构”：全景组件、真实前后端工程复用与依赖、职责和组件接口，决定系统**由什么构成**。
- 核心二“关键端到端业务链路”：从PRD核心场景筛选实际业务链路，画出**接入→校验→处理/判断→持久化→通知/外部动作→业务闭环及失败恢复**，决定每条业务**怎样运行**。
- 例如设备告警须确定数据上报后的校验、是否需要MQ缓冲、规则判断、告警幂等持久化、通知（如需）、人员处理（如需）及重复/乱序/通知失败处理。并非强制所有项目引入MQ、OSS或独立通知服务。
- 通过“链路步骤→组件Owner→交互/代码/数据权威”和“业务组件→实际关键链路/基础运行依据”双向核验，避免只有组件图而没有业务执行过程。
- 第二章围绕两个核心重组，其他容量、权限、部署、专项、Grill和A/B/C冻结作为支撑；五章结构、原流程与Matt官方原版保持不变。
