# 标准项目研发导航

面向已有确认的PRD、原型和前后端工程的定制项目，支持通用Web、IoT及Agent+Web首次建设、模块迭代、系统验收和生产交付。

- **在线导航**：https://wamper64.github.io/dev-workflow/
- **使用方式**：选择阶段→步骤→Skill，按“快速理解”查看执行链、必须明确的具体项、产物证据和失败退回；按实际项目资料执行，而非将示例当作已完成。
- **下载**：网站提供可离线使用的单文件HTML与Skills安装包。

## 一、项目输入

```text
项目根目录/
├── docs/
│   ├── input/
│   │   ├── 需求资料/       # 已确认PRD、原型及页面关联
│   │   ├── 工程资料/       # 已有方案、工程约束及技术选型
│   │   ├── 环境资料/       # 实际开发/测试/生产环境资料
│   │   └── 对接资料/       # 实际第三方或设备接口资料
│   └── output/            # 执行Skill得到的正式产物
├── code/                  # 原有前端原型及后端框架
└── skills/                # Skill安装目录
```

先读取真实输入，不补造未批准的PRD、服务器IP、第三方接口或实际验收结果。**前端在既有原型上开发，沿用现有组件和视觉风格；后端基于既有工程扩展，不重建另一套系统。**

## 二、研发主流程

| 阶段 | 当前执行顺序 | 核心产物 |
|---|---|---|
| 准备工作 | 展示已确认的 `docs/input/` 和 `code/` | 输入事实，不生成虚构文件 |
| 项目准备与设计 | 输入核验 → 初始化 → 项目基线 → 整体架构 → 数据库总体 → 初次部署 → 业务模块拆分 | 约束基线、组件与核心链路、数据规则与核心表/关系、真实环境配置/验收、模块池与依赖 |
| 模块迭代开发 | 本轮模块设计（含依赖/按需Grill）→ Matt to-spec → to-tickets → implement-spec → 人工测试与签收 → 按需Bug诊断 → Matt retro | 本轮范围、模块详细设计、独立Spec/Tickets、真实代码/TDD/Review、人测记录、签收及复盘建议 |
| 全项目验收与交付 | 系统业务验收 → 上线就绪 → 预检/回滚 → 生产部署交付 | 系统验收、非功能证据、预演和真实发布/交接 |

**固定职责**：项目基线只定义可量化或可判断的约束；整体架构同时固定组件职责/交互和关键端到端业务链路；数据库总体固定统一规则、数据生命周期及核心表/字段/关联ER；模块拆分以业务职责及核心对象生命周期为主判据，不按菜单、表或代码层机械拆分。

**按需故障诊断**：`/diagnosing-bugs` 可由开发异常、自动测试或CI失败、联调、人工测试、用户报告、设备/第三方或生产监控等实际故障触发，不必等到人工测试后。根据故障来源选择复现证据与修复后原检查/人测/现场验证；需生产操作时另行授权。导航中的位置只是常见闭环入口。

**迭代收口**：S09选择本轮任务并检查实际依赖，阻塞时不进Spec；S10/S11使用Matt原版；S12原版实现内含TDD和最终code-review；人工测试由独立Skill生成待执行用例并由真实人员回填和签收；未签收不更新完成状态。模块修改核心架构或数据Owner时返回总体设计审批。

**初次部署**：以真实项目 `code/deploy/single-node-docker/初次部署配置.md` 的完整八节为唯一配置依据，按环境数自动预填，一环境一文件；每环境**先获配置确认和部署授权**，再按其第8.1节提示词执行；首次只启动批准的基础设施、数据库和中间件，不启动尚未交付的业务应用或Nginx。执行后分别进行本机与异机验证并写环境专属结果。

## 三、Skill目录与来源

- 主流程和内部Skill：`skills/catalog.json`。
- 按需通用工具：`skills/workspace.json`，不与流程直接或内置使用的Skill重复展示。
- 来源、**具体借鉴的机制**与当前适配边界：[`skills/REFERENCES.md`](skills/REFERENCES.md)。
- 模板：`templates/project/`；其中部署配置模板不是可执行部署包，实际需配套项目Docker/SQL/SSH脚本。
- 独立案例：`docs/examples/报价项目/`，仅供理解产物深度，**不属于实际客户确认结果，也不进入安装ZIP**。

Matt原版的SKILL.md和其附件保持原文；自建Skill可适配定制项目，但不得在导航中伪称为Matt原版流程。所有“通过”必须有本次实际执行证据。

## 四、验证、构建与发布

```bash
python3 scripts/audit_contracts.py
python3 scripts/build_site.py
# 安装前端测试依赖后（详见.github/workflows/deploy.yml）
node scripts/smoke_ui.cjs
```

构建生成 `dist/index.html`（可脱网查看）和 `dist/skills-bundle.zip`。提交 `main` 后由 `.github/workflows/deploy.yml` 进行语法、静态契约、真实DOM交互回归与 GitHub Pages 部署；失败不发布。源码提交信息使用中文，仓库不存实际客户密钥、私有数据和未经脱敏的日志。

完整步骤输入/输出与质量门禁见 [研发流程契约](docs/研发流程输入输出与质量门禁.md)。
