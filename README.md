# 标准项目研发导航

面向**PRD和原型已确认、已有前后端工程**的定制项目，适用于通用Web，以及按需包含工业IoT、第三方系统、Agent的项目。提供首次项目建设从准备到上线的Skill工作流、输入输出约定、模板和人工审核门禁。

## 使用条件

- 输入：`docs/input/`的需求/工程/环境/对接资料及`code/`真实已有前端原型和后端框架；缺失时明确阻塞，不假定固定工程目录。
- 前端延续已有原型视觉和组件，后端延续既有框架。不得无批准另建一套页面、服务或数据Owner。
- 项目基线只定义工程**约束**；整体架构定义**总体组件结构和关键业务链路**；数据库总体定义**整体规则、关键数据生命周期、核心表/字段及ER关系**。
- 模块由业务职责、核心对象生命周期、可独立验收结果决定。Mock、示例及未经执行的命令不是验收成功证据。

## 当前完整研发流程

| 阶段 | 工作顺序 | 主要审核 |
|---|---|---|
| 准备工作 | 整理已确认需求和实际代码 | 资料可读取、输入可信 |
| 1. 项目准备与设计 | 输入核验 → Matt初始化 → 项目基线 → 整体架构 → 数据库总体 → 初次部署 → 模块划分 | 项目与架构基线批准；每环境配置先确认再执行；模块池和依赖经审核 |
| 2. 模块迭代开发 | 本轮任务与详细设计 → 官方to-spec → 官方to-tickets → 官方implement-spec → 独立人工测试与签收 → 按需diagnosing-bugs → 官方retro | 测试/审查用真实证据；人工结果由人员回填；已验收任务记录不覆盖 |
| 3. 全项目验收与上线 | 跨模块业务验收 → 非功能评审 → 发布/回滚预演 → 生产部署交付 | 按真实项目PRD和基线测量，生产必须有授权、回滚方案和业务签收 |

仓库提供 **4个阶段、20个导航步骤、19个主流程及内部Skill、8个通用入口**，加上必要的Matt内部依赖共**35份SKILL.md**。这些数量是导航和安装清单，不是预设的业务模块数量。

## 文件入口

- [在线研发导航](https://wamper64.github.io/dev-workflow/)；HTML源码位于`docs/`，步骤配置在`docs/data/quotation.json`。
- Skill定义及展示元数据：`skills/<id>/`、`skills/catalog.json`、`skills/workspace.json`。
- 任务与项目目录骨架：`templates/project/`及`docs/data/project-directory-tree.txt`。
- 示例：`docs/examples/报价项目/`，只解释使用方式，不代表真实客户资料或已批准设计。
- [当前输入输出契约和质量门禁](docs/输入输出契约与质量门禁.md)；[具体参考来源和采用方式](skills/REFERENCES.md)。

## 构建和发布

```bash
python3 scripts/audit_contracts.py
python3 scripts/build_site.py
# 安装jsdom并按CI相同路径配置后：
node scripts/smoke_ui.cjs
```

构建产物是`dist/index.html`（单文件离线网页）和`dist/skills-bundle.zip`。提交到`main`后，GitHub Actions执行静态契约、JavaScript和真实页面点击验证；通过才发布Pages。

## 职责和完成判据

| 角色 | 负责确认 |
|---|---|
| 项目经理 | 业务范围、角色×场景、模块归属、实际业务验收及客户签收 |
| 技术总监 | 工程约束、总体架构/数据Owner及冻结变更、非功能与上线放行 |
| 开发人员 | 实际工程与环境、模块详细设计、实现、自动验证、部署证据及技术签收 |

本仓库提供可执行**标准**，不表示特定项目已开发、部署或测试通过。真实项目的签收记录、Git历史和数据变更审计必须继续保留。
