# 报价系统 · 首次项目建设研发导航

**在线地址**：https://wamper64.github.io/dev-workflow/

本仓库是定制前后端系统首次建设的研发步骤导航与Skill工作区。目前仅审核、建设**报价系统研发导航**；标准项目研发导航待报价系统版本确认后再建。

## 固定输入与边界

```text
项目根目录/
├── docs/
│   ├── input/
│   │   ├── 需求资料/       # 已确认PRD，包含原型页面映射
│   │   ├── 工程资料/       # 前期架构、方案、技术选型（可选）
│   │   ├── 环境资料/       # 服务器/开发环境（可选）
│   │   └── 对接资料/       # 第三方或设备接口（可选）
│   └── output/            # 各阶段正式产物
├── code/
│   ├── fld/               # 既有前端原型——必须在此基础上开发
│   └── guiwu_ruoyi/       # 既有后端若依框架——必须复用扩展
└── skills/                # 工作区各Skill
```

严禁在原型之外重搭一套风格；业务开发可改页面数据及小范围细节，不重做已有原型视觉与通用组件。已确认的PRD不在本阶段重新制定。

## 网站

左栏为工作阶段，中栏为步骤，右栏为所用Skill、输入、输出、审核和可复制中文提示词。点击Skill可以选择按其特点设计的快速理解、报价项目示例、完整目录文件以及**逐文件开源研究来源与实际借鉴机制**。

右上角“通用 Skills”可浏览handoff、grilling、domain-modeling、research等按需调用的官方Skill；下载“全部Skills”可得到安装文件包。研究说明不进入安装包中的SKILL.md正文。

## 当前流程

| 阶段 | 工作内容 |
|---|---|
| 0 准备工作 | 展示已确认docs/input/资料与既有code/，不调用Skill |
| 1 项目准备与设计 | 输入确认→Matt初始化→项目基线→架构Grill→整体架构→数据库总体→开发环境→模块拆分 |
| 2 模块迭代开发 | 选择本轮模块→按需模块Grill→详细设计→to-spec→to-tickets→implement-spec(TDD)→code-review(Standards+Spec)→自动联调/原型检查→人工测试→有Bug才诊断修复并全链路复测→收口 |
| 3 全项目验收与部署 | 系统业务验收→非功能上线评审→生产预演与回滚→正式部署交接 |
| 4 复盘与沉淀 | Matt编码会话retro→项目级流程与Skill改进 |

共**5个阶段、27个导航步骤（包括第0阶段2项输入展示）**，25个可执行步骤引用**24个主Skill**（Grill被两个决策步骤复用）。另外有6个通用工具Skill及3个必要官方依赖，共**33份SKILL.md**。实际模块数量须从PRD识别；报价项目目前展示的13个模块只是待审核候选分组。

## Skill质量与采用原则

- **Matt官方原版**：在不更改内容的前提下复用，不重写成“二次封装”。
- **基于Matt改造或自建**：先研究真实开源SKILL.md，按定制前后端、原型保真、若依复用、角色审核和真实证据规则改造。
- **项目基线**：已采用现有较成熟的工程基线Skill方案，包括技术栈、资源量化、数据保存年限、性能和并发指标；不默改其内容。
- **其他自建/改造**：已补齐专项执行流程、可判断检查关卡、产物模板和报价业务示例，目前为**可评审初版**，仍需真实项目演练和人工确认，不以模板齐全代表已成熟。
- 来源及“参考了什么机制”：见 [逐Skill调研记录](docs/research/skill-sources.md)。研究资料独立于可安装Skill正文。

## 自动发布与保护

GitHub Pages源设置为 **GitHub Actions**。每次提交`main`后，`.github/workflows/deploy.yml`构建带内联资源的网站及Skills ZIP，并测试基本的阶段、步骤、Skill目录、Grill、人工测试和通用工具交互。CI失败不发布。

开发约定：所有Git提交消息使用中文；本公开仓库不存真实客户PRD、生产密码或未脱敏接口数据。
