# 单机 Docker 首次部署配置模板

本文档用于填写单个环境的首次部署参数。首次部署只部署服务器基础环境、数据库和中间件，不部署后端应用和前端入口。

首次部署没有后端 jar 包，也没有前端 dist；不得启动 `ruoyi` 或 `nginx`，不得执行会检查 jar/dist 的应用部署入口。必须在本地部署包和远程部署目录中预留 `package/ruoyi-admin.jar` 与 `package/dist/` 的放置位置，后续把文件放进去即可执行应用发布。

本环境必须独立于服务器上已有项目：独立部署目录、独立 Compose 项目名、独立容器/网络/volume 命名前缀、独立宿主机端口、独立数据库名、独立历史库名、独立 Redis database/prefix、独立 RabbitMQ vhost。不得复用已有项目的容器、网络、volume 或部署目录。

## 1. 部署服务清单

AI 只根据“是否部署”填写为 `是` 的组件执行部署或配置；执行前必须学习当前部署包 `code/deploy/single-node-docker/`，判断当前部署包是否支持对应组件。

| 配置项 | 填写值 | 可选值 | 说明 |
| --- | --- | --- | --- |
| 本次部署环境 |  | `开发环境` / `正式环境` | 用于决定本次读取哪一套私有环境配置文件；同一个部署包同时维护开发和正式环境时，必须分别保存环境配置，避免互相覆盖。 |

| 组件 | 是否部署 | 说明 |
| --- | --- | --- |
| PostgreSQL |  | 主业务库；使用独立数据库和数据卷。 |
| Redis |  | 使用独立 Redis 容器；同时区分 Redis database 和 key prefix。 |
| RabbitMQ AMQP |  | 使用独立 RabbitMQ 容器和 vhost。 |
| RabbitMQ 管理端 |  | 开放独立管理端口。 |
| TimescaleDB / 历史库 |  | 随 PostgreSQL 容器启用 TimescaleDB 扩展，不单独启动 `timescaledb` 服务。 |
| 初始化 SQL |  | 首次创建 PostgreSQL 数据卷时自动执行 `sql/init`。 |
| FTP 文件存储 |  | 如启用，部署独立 FTP 容器，使用独立控制端口和被动端口范围。 |
| MQTT / EMQX |  | 如启用，必须确认当前部署包支持对应服务，并填写端口、账号和验收方式。 |

本次首次部署命令模板：

```bash
docker compose --env-file .env -f docker-compose.yml -f docker-compose.db-port.yml -f docker-compose.ftp-build.yml up -d postgres redis rabbitmq ftp
```

按实际部署清单调整最后的服务名；首次部署阶段不得启动 `ruoyi` 或 `nginx`。

### 1.1 环境配置文件命名规则

如果同一个本地部署包目录需要同时维护开发环境和正式环境，不要长期共用单个 `.env` 或 `remote.env`。建议使用以下私有文件分别保存：

| 环境 | 本地 SSH 配置文件 | 本地 Compose 配置文件 | 说明 |
| --- | --- | --- | --- |
| 开发环境 | `remote.env.dev` | `.env.dev` | 部署开发环境前，从开发配置生成或复制到实际执行入口需要的 `remote.env` / `.env`。 |
| 正式环境 | `remote.env.prod` | `.env.prod` | 部署正式环境前，从正式配置生成或复制到实际执行入口需要的 `remote.env` / `.env`。 |

实际远程服务器部署目录中仍可以使用 `.env`，但开发环境和正式环境必须使用不同的 `REMOTE_DIR`。每个远程部署目录只保存本环境自己的 `.env`，不得把另一个环境的 `.env` 上传到当前目录。

执行前必须确认当前 `.env` 来源于“本次部署环境”对应的私有配置文件；切换环境时先重新生成或复制 `.env`，再执行 Docker Compose 命令。

## 4. 端口配置

只填写本次部署服务需要暴露的端口。未部署或不需要另一台电脑访问的组件可留空。同一台服务器上的所有宿主机端口必须和已有项目端口不同。

| 配置项 | 填写值 | 默认值 | 说明 |
| --- | --- | --- | --- |
| HTTP 预留端口 |  | `80` | 首次部署不启动 `nginx`，该端口仅供后续应用发布使用。 |
| PostgreSQL 宿主机端口 |  | 留空 | 另一台电脑需要连接数据库时使用。 |
| Redis 绑定地址 |  | `127.0.0.1` | 需要局域网验收访问时填写 `0.0.0.0`。 |
| Redis 宿主机端口 |  | `16379` | Redis 外部访问端口。 |
| RabbitMQ 绑定地址 |  | `127.0.0.1` | 需要局域网验收访问时填写 `0.0.0.0`。 |
| RabbitMQ AMQP 端口 |  | `5672` | 客户端连接端口。 |
| RabbitMQ 管理端口 |  | `15672` | 管理页面端口。 |
| TimescaleDB / 历史库端口 |  | 同 PostgreSQL | TimescaleDB 是 PostgreSQL 扩展，和 PostgreSQL 使用同一个容器、同一个端口。 |
| EMQX 绑定地址 |  | `0.0.0.0` | 未部署 MQTT / EMQX 时留空。 |
| MQTT 端口 |  | `1883` | 未部署 MQTT / EMQX 时留空。 |
| EMQX Dashboard 端口 |  | `18083` | 未部署 MQTT / EMQX 时留空。 |
| FTP 绑定地址 |  | `0.0.0.0` | 需要局域网验收访问时填写 `0.0.0.0`。 |
| FTP 端口 |  | `21` | FTP 控制端口。 |
| FTP 被动端口范围 |  | `21100-21110` | FTP 被动模式端口范围，需要和服务器防火墙一起放行。 |

对应 `.env` 字段；如同一部署包维护多个环境，应先写入 `.env.dev` 或 `.env.prod`，执行前再生成本环境实际使用的 `.env`：

```env
HOST_HTTP_PORT=
DB_HOST_PORT=
REDIS_HOST_BIND=
REDIS_HOST_PORT=
RABBITMQ_HOST_BIND=
RABBITMQ_HOST_AMQP_PORT=
RABBITMQ_HOST_MANAGEMENT_PORT=
FTP_HOST_BIND=
FTP_PORT=
FTP_PASV_MIN_PORT=
FTP_PASV_MAX_PORT=
```

## 8. AI 执行要求

### 8.1 推荐提示词

把本文档确认后，可以把下面这段提示词连同本文档一起给 AI：

```text
你现在负责执行本项目首次部署。
只读取并依据本《初次部署配置.md》执行，不要依赖其它部署说明文档。
执行方式：在本地电脑通过 SSH 和部署脚本连接真实被部署的 Linux 服务器完成部署。

要求：
1. 先读取本文档，检查“本次部署环境”和“填写值”是否完整。
2. 根据“部署服务清单”判断本次要部署哪些组件，并根据“开机自启动配置”判断是否为所有实际部署组件配置开机自启动。
3. 按“一套环境一套独立 Docker Compose 容器组”执行：检查远程部署目录、Compose 项目名、容器/网络/volume 命名前缀和宿主机端口，不得与服务器已有项目冲突。

7. 执行前先汇报将要执行的命令、会开放的端口、会上传或修改的文件。
8. 部署后做服务器本机验证，并按本文档要求完成另一台电脑访问服务器 IP 和端口的连通性验收。
9. 部署成功后，在本地部署电脑的 code/deploy/single-node-docker/ 生成部署结果 README，记录实际部署组件的部署信息和连通性；服务器远程部署目录可同步副本，但最终回报必须优先给本地路径。
```

### 8.2 AI 根据本文档执行部署步骤

1. 读取本文档，确认第 1 节“本次部署环境”和“部署服务清单”中哪些组件填写为 `是`，读取第 2 节“开机自启动配置”，并读取第 3 节中的项目/程序标识、Docker Compose 项目名和远程部署目录。
2. 学习当前部署包 `code/deploy/single-node-docker/`，确认组件是否可部署。
3. 通过 SSH 登录服务器，检查是否已经存在其它项目、容器和端口占用。至少执行：

```bash
docker compose ls
docker ps --format 'table {{.Names}}\t{{.Ports}}'
ss -lntup || netstat -lntup
```

4. 按“一套环境一套独立 Docker Compose 容器组”校验配置：`REMOTE_DIR` 不得复用已有项目目录，`REMOTE_COMPOSE_PROJECT_NAME` / `COMPOSE_PROJECT_NAME` 不得复用已有项目名，所有需要暴露到宿主机的端口不得和已有监听端口冲突。如发现冲突，停止部署并要求修改配置后再继续；不得复用已有项目容器、网络、volume 或部署目录。
5. 生成本地私有环境配置文件。单环境部署可使用 `remote.env` 和 `.env`；同一部署包维护开发和正式环境时，必须分别保存为 `remote.env.dev` / `remote.env.prod` 和 `.env.dev` / `.env.prod`。
6. 按第 4 节和第 5 节生成服务器部署目录下的 `.env`。真实密码只写入私有配置文件，不写入最终回复。`.env` 中必须写入唯一的 `COMPOSE_PROJECT_NAME`，确保本环境容器、网络和 volume 有独立命名前缀。部署前必须确认服务器 `.env` 来源于当前“本次部署环境”对应的私有配置文件。
7. 如果第 1 节选择部署 PostgreSQL 且第 7 节要求初始化数据库，确认初始化 SQL 目录中已存在本次首次部署需要的 SQL 文件。
8. 首次部署不检查 `package/ruoyi-admin.jar` 和 `package/dist/`，不启动 `ruoyi` 或 `nginx`，不执行会检查 jar/dist 的应用部署入口；但必须保留 `package/` 和 `package/dist/` 目录，作为后续 jar 和 dist 的上传位置。
9. 上传 `code/deploy/single-node-docker` 部署包到远程部署目录。
10. 在远程服务器部署目录执行 Docker Compose，按实际部署组件调整服务名：

```bash
docker compose --env-file .env -f docker-compose.yml -f docker-compose.db-port.yml -f docker-compose.ftp-build.yml up -d postgres redis rabbitmq ftp
```

11. 执行后检查容器状态和本机健康状态：

```bash
docker compose --env-file .env -f docker-compose.yml -f docker-compose.db-port.yml ps
docker compose --env-file .env -f docker-compose.yml -f docker-compose.db-port.yml exec postgres pg_isready -U "$POSTGRES_USER" -d "$POSTGRES_DB"
docker compose --env-file .env -f docker-compose.yml -f docker-compose.db-port.yml exec redis redis-cli -a "$REDIS_PASSWORD" --no-auth-warning ping
docker compose --env-file .env -f docker-compose.yml -f docker-compose.db-port.yml exec rabbitmq rabbitmq-diagnostics -q ping
docker compose --env-file .env -f docker-compose.yml -f docker-compose.db-port.yml -f docker-compose.ftp-build.yml ps ftp
```

12. 如需停止服务，只能执行普通停止；不得删除 volume，除非用户明确确认要重建数据库：

```bash
docker compose --env-file .env -f docker-compose.yml -f docker-compose.db-port.yml stop
```

| PostgreSQL |  | 服务器本机 `pg_isready` 通过；另一台电脑可连接对应端口。 |

| RabbitMQ AMQP |  | 容器状态正常；另一台电脑可连接对应端口。 |

| FTP 文件存储 |  | FTP 容器运行正常；另一台电脑可登录并完成目录访问或文件传输验证。 |
| MQTT / EMQX |  | 如启用，按部署包支持能力验证服务状态、端口连通性和 Dashboard。 |

部署成功后，AI 必须在本地部署电脑的 `code/deploy/single-node-docker/` 生成：

```text
部署结果README.md
```

部署结果 README 是给部署人员在本地部署电脑查看的结果文档，只记录本次实际部署的组件，不要把未部署组件全量列入模板。可选再同步副本到服务器远程部署目录作为现场副本，但不能只生成在服务器上。必须使用以下格式：

```markdown
# 部署结果 README

本文档由 AI 在首次部署成功后生成。不得写入完整密码、私钥、token 或其它敏感值。

## 1. 部署信息

| 组件 | 部署位置 | 服务名 | 端口 | 数据/配置位置 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 本次实际部署的组件名称 | 服务器 IP、远程目录或容器名 | Compose 服务名或不适用 | 宿主机端口 -> 容器端口，或不适用 | 数据卷、SQL 目录、配置文件路径等 | 验收结论或必要说明 |

## 2. 组件 IP、端口和连通性

| 组件 | 服务器 IP | 端口 | 连通性 |
| --- | --- | --- | --- |
| 本次实际部署的组件名称 | 服务器 IP | 对外验收端口，或未暴露端口 | 可连通 / 不可连通 / 未暴露端口 / 待人工验证 |
```

连通性结论只能填写：

- `可连通`
- `不可连通`
- `未暴露端口`
- `待人工验证`
